# 按名字查找：统一标准

> 立：2026-11-19。适用范围：**一切"给一个名字，换回一个东西"的代码**。
> 这不是风格建议。下面每条规则都对应一次真机事故，事故写在 §4，改之前先看那节。

---

## 0. 为什么要有这份标准

这个仓库里"查找"有四种，而且四种都长过重复实现：

| 查找 | 输入 | 输出 | 现状实现 |
|---|---|---|---|
| 反射读成员 | 对象 + 成员名 | 值 | ✅ `csharp/game/Refl.cs`（11-19 由 7 份收成 1 份） |
| 单位 | 名字 / unitID | `WorldUnitBase` | ✅ `csharp/game/UnitLookup.cs`（16 个文件在用）；反向取名字/取 id 是 `UnitIdentity.cs` |
| UI 节点 | 层级路径 | `Transform` / `Component` | ✅ `csharp/UI/UiKit.cs`（11-19 批次 4 第 1 步：`FindGo`/`FindRt`/`FindTr`/`FindByPath` 共 11 份 → 1 份） |
| 配表行 | id / 字符串 key | 行对象 | ✅ `g.conf.*.GetItem(...)`（游戏自己的入口，我们只许判空，不许假设） |

四种查找的失败方式**一模一样**：不抛、不报、返回空，然后调用方把"读不到"当成"没有"。所以标准也只有一套。

## 1. 硬规则

### R1 单一实现
同一类查找，全仓只能有一处实现。新需求**改它**，不许在旁边再写一份。
判据不是"看着像"，是它能被一条源码契约测试钉住（见 §5）。

### R2 名字集中且可 grep
成员名、节点路径这些字符串，必须能一处改、全仓生效。禁止把同一路径在四个文件里各写一遍
（当前 `AbChatPanel` / `AbConfigPanel` / `AbContactPanel` / `NoticePanel` 就在各写各的节点路径 ——
批次 5 的活儿，先记在这）。

### R3 必须带缓存
同一「对象类型 + 名字」只允许解析一次。这些查找点在战斗采样、每次开窗、每帧回调里都会被反复调用，
没有缓存的反射/字符串查找是白白付出的成本。

### R4 失败必须可观测
返回空之外，**必须留一行日志**，并且：

* 同一「类型 + 名字」只打一次（去重）；
* 全进程封顶（现用 40 条），到顶时打一条"已达上限"的提示；
* 日志里要有**类型名 + 名字**，能直接回答"我们在向谁要什么"。

没有这行日志，就等于这个查找点永远无法排障 —— 这是本仓历史上最贵的一类问题（见 §4.1）。

### R5 禁止猜
不许"读不到就换一条路再猜"。回退链只允许**语义明确的并列入口**：

* 允许：`Get`（属性）与 `GetField`（字段）是两个入口，由调用方声明它要哪个；
* 允许：`Name`（取不到给调用方兜底）与 `NameOr`（三种空值分开兜底）是两个入口；
* 禁止：属性读不到→再查字段→再试索引器→最后按名字扫全图。这条链让"读不到"和"值就是空"彻底混在一起。

### R6 兜底词归调用方
`""` / `"?"` / `"(空)"` / `"(无名)"` 这类**显示语义**不进查找实现。查找实现只回空，
由调用方决定怎么展示。否则同一个空值会在三个模块里变成三种字面量，排障按名字 grep 会漏。

### R7 调用点不许再包 try/catch
实现已经保证**绝不抛**。调用点再包一层，只会让"是谁失败"更模糊，还会顺手吞掉真正的异常。
如果确实需要保护（比如后面还有别的会抛的语句），那段 try 的注释里要写明它保护的是什么。

### R8 每个查找点都要能被真机日志回答两个问题
1. **读到了没有？**
2. **读到的是什么类型的值？**

答不上来的查找点，等于没接。

## 2. 各类型的细则

### 2.1 反射读成员（`Refl`）

* 只读**属性**（`Get`）。Il2Cpp 代理把原生数据字段暴露成属性；真正的字段只能由
  `GetField` 读，且必须沿 `BaseType` 上找。
* 不要用 `dynamic` 索引器兜底：代理类型没有索引器，走到必抛必吞。
* 值转换用 `Bool` / `Int` / `Str`，带显式兜底值；不要在调用点写 `Convert.ToXxx`。

### 2.2 单位（`UnitLookup` / `UnitIdentity`）

* 查人用 `UnitLookup.Resolve(名字)`；**有精确 unitID 时必须用它**（`ResolveEx`），按名字是最后手段 ——
  同名会把结果挂到别人身上，而且不报错。
* 取名一律 `UnitIdentity.Name(u, 兜底)`；取 id 一律 `UnitIdentity.Id(u)`（取不到是空串，不是 null）。
* 判定"这是不是玩家"不许用 `ReferenceEquals`（IL2CPP 下同一原生对象可能给不同托管代理）——
  比 unitID。

### 2.3 UI 节点（`UiKit`）

* `UiKit.FindByPath` 是唯一实现（逐段匹配，与 active 无关）；`FindGo` / `FindRt` / `FindComp` 都是它的薄封装。
* **禁止 `Transform.Find`**：模板里的节点出厂是关的，`Find` 会静默跳过未激活节点（10-23 实机：点一次循环一次，屏幕毫无反应）。
* 节点路径字符串集中在各面板的 `CollectRefs` 里，**一处一份**，不许同一路径在两个文件里各写一遍。
* 取 `RectTransform` 只能走 `UiRects.Of`，禁止 `as RectTransform`（静默 null，见 §4.2）。

### 2.4 配表行

* 一律 `GetItem(...)` 后**立刻判空**，空就走"表里还没有这一行"的分支并打日志；
  不许假设表已导出（玩家侧的导出时机不受控）。
* 运行时补行（`RoleLogTemplate`）必须**同时补索引**，否则引擎静默丢弃（见 §4.4）。

## 3. 新增一个查找点时的 checklist

1. 这是哪一类查找？去找它**已有的唯一实现**，不要新建。
2. 名字是什么？能不能写成常量/字面量集中在一处？
3. 它会在每帧 / 每次开窗被调用吗？→ 需要缓存。
4. 读不到时调用方怎么表现？→ 先决定"空"的语义，再决定日志文案。
5. 兜底词是什么？→ 留在调用点，不进实现。
6. 加一条契约测试钉住"只有一份实现"（照 `tests/test_refl_single_source_contract.py` 写）。
7. 想清楚真机上看哪一行日志能证明这个查找点在工作。

## 4. 反例清单（每条都是真事故）

### 4.1 同一判据两种实现，结论相反
气运判定：产品侧 `TeamTool.HasLuck`（只查运行时层）与探针侧 `HasLuckAny`（运行时层 ∥ 存档层）。
结果是探针"证明"已清空、引擎仍看得见。**同一个问题，两种算法，两个结论，都不报错。**

### 4.2 `as RectTransform` 静默返回 null
09-13 两次实机事故；11-19 又踩一次：气泡宽度整条策略失效，因为气泡盒的转型恒为 null，
而当时的日志"只在写成功后打"——于是**一个字都没有**。正确写法只有 `UiRects.Of`。

### 4.3 `dynamic` 索引器兜底
7 份反射实现里只有 1 份有它。它读得到的东西属性档都读得到，代价是让那 1 处与另外 6 处语义不同，
而且走到就抛、就被吞。

### 4.4 `AddItem` 不补索引 → 引擎静默丢弃
`ConfRoleLogLocal::AddItem` 尾部只有一句 `List::Add`（8 字节，反编实证），不碰 `allItemInKey`。
只注册不补索引 ⇒ `GetItem` 查得到、写经历全丢。两份实现曾在这里漂移，其中一份没补。

### 4.5 空值语义 12 种写法
取名字/取 id 曾包了 12 遍，空值分别给 `""` / `null` / `"?"` / `"(空)"` / `"(无名)"` / `"(取不到)"`。
后果不是崩溃，是日志里同一件事有三种写法，排障 grep 会漏。

## 5. 验证分层（每一类查找都必须能过这三层）

| 层 | 做什么 | 现在的例子 |
|---|---|---|
| ① 单元测试 | 把实现链进 net8.0 控制台工程，断言"静默行为"：读不到回空、基类成员能找到、`new` 隐藏取最派生、缓存生效、日志去重与封顶 | `csharp/tests/ReflTests`（24 条）。**必须做变异验证**：故意改坏，确认测试会红 |
| ② 源码契约 | 钉住"只有一份实现""没有禁用写法""调用点没包 try/catch" | `tests/test_refl_single_source_contract.py`（7 条） |
| ③ 真机日志 | 证明它在这个 IL2CPP 环境里真的读到了 | `[Refl] 读不到：类型.成员` / `[Refl] 读取异常`；UI 侧另有 `[UiKit] 节点缺失` 与 `[UiKit] 建树自检` |

**层 ①② 能证明"接法是对的"，证明不了"这个名字本身是对的"。** 名字的正确性只能靠
反编 dump 核对 + 真机日志。不要把单测全绿当成"功能一定好使"。
