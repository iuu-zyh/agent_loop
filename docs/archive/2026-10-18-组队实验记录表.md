## 一、字段含义速查（避免每次重新查）

`DungeonTrigger.battleFunction` 里跟"生成人"有关的命令，**只有三条**：

| 命令 | 参数 | 官方原文 | 已确认的语义 |
|---|---|---|---|
| `addBattleNPCData_<NpcConditionID>_<索引>` | 组ID、索引 | 「将…NPC组中**第一个** NPC 加入**战斗NPC容器**中」 | 只进容器，**场上不出现**。原版仅 `133/134` 用于救人剧情 |
| `addBattleUnit_<X>_<x>_<y>_<entry>_<pause>_<team>_<drama>_...` | 第一参数是"战斗单位ID" | 战斗单位ID表：`1`玩家 / `2`当前副本NPC / `3`其他NPC1 / `4`其他NPC2 / `5`其他NPC3 / **`#NpcCondition的ID`（抓取NPC）** / 其他=怪物ID | `X` 传**条件组ID** = 现场按条件抓人；传 `3/4/5` = 取列表位置 |
| `addBattleUnit_<NpcConditionID>&<N>_...` | 组ID `&` 第N个 | **教程里完全没有这个语法** | 从原版 `22201` 反推：`100801&0..&4` 配 5 段条件组 → 出 5 人 |

`addBattleUnit` 后面 9 个参数（官方 `副本作用功能` 第 52 行）：

```
x坐标: -1玩家面前 / -2地图中心 / -3npc面前 / -4玩家身后随机位置
y坐标: x=-3 时 = 战斗单位id；x=-4 时 = 限制区域正方形边长
进场方式: 1直接出现 / 2移动进场
暂停: 0/1
队伍类型: 1玩家方召唤物 / 2盟军 / 3怪物方 / 4不参战
剧情ID / 朝向1左2右 / 跟随玩家0否1是 / 换房间隐藏0否1是 / 重置剧情单位0否1是
```

#### E08 到底哪一项起了决定作用？（还不能定论，但有强线索）

从 E05（0 人）到 E08（1 人），**同时变了 5 个变量**：`condition`、`dramaFunction`、`probability`、`save`、段数。
按"一次只改一个变量"的原则，这是不合格的实验。但已确认"逐字照抄组队 mod"整体有效。
**下一步必须在 1 人成功的基础上，一次只回退一个变量**，才能知道哪些是必需的（见 E09）。
