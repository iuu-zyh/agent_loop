# 自我人设：玩家自述作为 system 的一段

> ⚠ **已归档**。本文是一次性排查记录，没有对应的现状文档，**日常开发不用看**。
>
> **结局**：`config.json` 的 `player.persona` 成为唯一真相源，冲突时以游戏事实为准。

---

**需求**：配置文件新增一个"自我人设"（玩家的人设信息），默认空，作为 system prompt 的一段。

**分工（别和已有东西搞混）**：L1 上下文的「玩家」段是 **C# 从存档读出来的游戏事实**（姓名/性别/
修为/宗门/关系·好感/位置/魅力/声名/心情，`system_prompt.py:677-737`）；自我人设是**玩家自述**
（身份、来历、性情、说话习惯、希望被怎么称呼）。两者**互为补充**，冲突时以游戏事实为准 ——
这条裁决规则写进包裹模板里，否则玩家自封"我是你师父"会和 `relationships` 的结果打架。

**存储**：`config.json` 的 `player.persona`（唯一真相源）。
| 决策 | 取值 | 理由 |
|---|---|---|
| 默认 | `""` | 空 = **段根本不存在** ⇒ 与不启用本功能时 system **逐字节相同**（零回归，有测试锁） |
| 上限 | 4000 字，**fail-closed 拒收** | 这段每回合都进 system（真实 token 成本）；静默截断会把玩家写的人设切一半还不告诉他 |
| 空串语义 | **照原样写回**（不删键） | 与 `llm.headers`（空 = 删键）刻意相反：空是"我不要这一段"的明确表达，删键会让玩家看不出自己设过什么 |
| 生效 | 热生效块（`HOT_BLOCKS += "player"`） | `SystemPrompt` 是进程单例的全局屉，重新注入即可；**不必重启 Python，更不必重启游戏** |
| 作用域 | 全局 | 所有 NPC / 所有存档 / **群聊也生效**（群聊复用同一个 SystemPrompt）；per-NPC 或 per-存档要另设计存储，不做 |

**注入**：`SystemPrompt.set_player_persona(text)` → 全局 section `config:player_persona`，
order **-70**（在 `world:persona_rules`(-80) 之后、`deployment:persona`(0) 之前）。
顺序两个约束：规则要在自述之前（不被自述顶掉）；**稳定段必须压在 per-NPC 段之前**，
否则每换一个 NPC 都废掉 provider 侧的提示词前缀缓存。`_SYS_LABELS` 加 `"自我人设"`。
文本用固定模板包裹（`PLAYER_PERSONA_TEMPLATE`）：交代"怎么用"「别复述」「别提设定」+ 冲突裁决。
**注入口唯一**：装配层 `server.install_player_persona()`（`get_loop` 里一次 + `ConfigService.set_config`
的 `player.*` 热落地分支一次）—— 各组件不 import `config_loader` 的约定不破。

**差分（用户问的"系统组装"那一块）**：不用写新逻辑。`dialogue_agent._step` 的段级差分天然覆盖：
首步全列（含「自我人设」一行）→ 之后只有变化的段上行 → 改人设时**只上行这一段** →
清空后下个回合**不再出现**（注意 `sys` 没有 `ctx` 那种「（已移除）」行）。`dev/sys-snapshot`
存全量段快照，resume 不会重播未变的段。测试用**真跑回合 + 收集 on_step 帧**验这三步。

**UI 落点（不再动预制件/不重打 AB）**：挂在**提示词页**，是一条 path 前缀 `config:` 的
**虚拟条目**「自我人设（玩家）」（Python `prompt_files.list_prompts` 排在第一位、`deletable=False`、
带 `label` 与悬停说明）。选它的理由：那一页已经有**多行编辑器 + 保存键**；配置页的
`BG/PageLlm/Scroll/Viewport/Content` 是**绝对定位**的（Content 上没有 VLG），插一行要重排其后所有
行的 y 坐标，还得重打 AB。
C# 三处分流（缺一不可，契约测试锁着）：
| 处 | 规则 |
|---|---|
| `SelectFile` | 虚拟条目**不发** `read_prompt`（Python 对 `config:` 路径 fail-closed 拒绝），改用 `get_config` 缓存值填编辑框 |
| `SavePromptFile` | 虚拟条目**从批量 `write_prompts` 的 files 里剔除**（Python 批量写是 fail-fast：混进去整页保存一起失败），单独走 `set_config` |
| `SavePersona` | **空串照提交**（= 清空）；载荷构造→发送之间不许有分支 |
另两条细节：`FillPersonaEditor` **脏值优先**（`_promptCache` 里有未保存的编辑就用它，
免得 `get_config` 刷新把用户正在写的东西冲掉）；读值一律 `.ToString()`，
`?.Value<string>()` 在"键存在但值为 JSON null"时会抛 `InvalidCastException`（本仓库踩过的同款）。

**测试**：`tests/test_player_persona.py`（16 项：配置归一/注入与移除/order/标签/变量插值/
真回合差分三连/虚拟条目/`ConfigService` 热落地）+ `tests/test_player_persona_ui_contract.py`
（13 项 C# 接线契约）+ 变异验证 **20 项**（`scripts/dev/mutate_check_player_persona.py`，
Python 12 + C# 8，逐条回退确认变红）。
变异验证当场抓出一个洞：C# 「空串不提交」那条变异原本**没被抓到**（我原来只查字面量
`persona.Length > 0`，而变异写成 `(persona ?? "").Length == 0` 就绕过了）→ 改成结构性判据
"载荷构造到发送之间不许有分支/提前返回"后才抓住。

**已知取舍**：① 面板里人设这一行的显示名/说明由 Python 下发（`label`/`desc`），老端回落
"分组中文名/文件名"；② 未做"称呼"独立键（写在人设文本里即可，模板已提示）；③ 人设不进压缩摘要
也不需要进（它是每回合重注入的常驻段）。
