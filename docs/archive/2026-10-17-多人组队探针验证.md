# 多人组队探针 —— 验证清单

> ⚠ **已归档**。现状见 [`docs/features/team.md`](../features/team.md)。本文只保留当时的排查过程与被推翻的中间结论，**追溯「这个结论怎么来的」时才需要读**。
>
> **结局**：三趟实测定案：容器 5 槽位但只能「一槽一人」，`setNPCA` + `addBattleUnit_3/4/5` 是正解。
>
- **起止**：2026-10-17
- **触发**：组队 mod 到底只能带 1 个人还是能带多个 —— 这个结论决定工具是「兼容」还是「自建表」
- **涉及**：`csharp/diag/team/TeamMultiProbe.cs`

## 为什么必须实测

配置里只有一行：

```
addBattleNPCData_MID&003_0
                      └─ 索引，官方文档只说"索引"，不说行为
```

三种可能，改法完全不同：

| 可能 | 现象 | 后续改法 |
|---|---|---|
| A. 索引 0 只取第一个 | 挂 3 个，上来 1 个 | 要写多行 `_0`/`_1`/`_2` |
| B. 引擎自动全上 | 挂 3 个，上来 3 个 | **什么都不用改** |
| C. `addBattleUnit` 只能生成 1 个 | 挂 3 个，上来 1 个（但容器有 3） | 要用 `&` 索引语法 |

**静态分析（反编译只有签名、无方法体）无法区分。只能进游戏数单位。**

## 操作步骤

### 第 1 趟：确认人能找得到（只读，零风险）

1. 启动游戏，勾选**组队 mod**（必须），进入存档
2. 保持开关 `action=scan`，在城里站 10 秒
3. 退出游戏

我读 `team_multi_summary.txt` 确认：
- 全图 NPC 总数
- 「结伴而行」是否被按名反查命中（= mod 已加载）
- 当前谁身上有该气运

### 第 2 趟：多人实测（改存档状态）

开关已预置为：

```ini
action=givemap
radius=1
```

1. 启动游戏，进存档，**走到 2~3 个 NPC 旁边站好**
2. 等 10 秒（`givemap` 自动给周围半径内所有 NPC 挂气运）
3. **改成** `action=dumpbattle`（改文件立即生效，不用重启游戏）
4. **进入任意一个普通副本**（如炼气期的秘境）
5. 进副本后**站 5~10 秒**（让 `BattleTrigger14` 的 1000ms 定时器跑几轮）
6. 退出游戏

> 为什么用 `givemap` 而不是 `give`：`give` 要手填真实 NPC 名，而这游戏**重名是常态**
> （`UnitLookup` 文件头记着按名解析拿到过另一个同名者的事故）。`givemap` 让探针自己
> 报告"挂了谁"，不靠猜。周围没 NPC 时才退回 `action=give` + `names=`。

我读 summary 得到结论：
- 战斗单位总数
- NPC 类单位数 ← **这就是"上来几个人"**

### 第 3 趟（清理，可选）

```ini
action=clear
```

进去站 10 秒即清除。或者直接读档（不保存就没影响）。

## 判读要点

| summary 里看到 | 含义 |
|---|---|
| `带「结伴而行」= 3 个` | 气运挂载成功，3 人都标记了 |
| `NPC类单位 = 1` | **确认只能带 1 人** → 要写多行配置 |
| `NPC类单位 = 3` | **引擎自动全上** → 什么都不用改 |
| `带「结伴而行」= 0 个` | 气运没挂上，看 log 里的异常 |
| `不在副本/战斗中` | 没进副本，或 `isBattle` 判据没生效 |
| `拿不到 SceneBattle 实例` | 反射失败 → 退化为全局扫描，仍能数单位但缺 battleData |

## 已知的探针局限

1. **`SceneBattle` 靠反射获取**。引擎里它没有 static 成员，唯一持有者是
   `SceneType.battle`；`SceneType` 是否为静态单例未验证。拿不到时不崩，
   只是少了 `battleData` 那部分信息（`wvTeamIn_*` key）。
2. **NPC 名字必须精确**。`UnitLookup.Resolve` 支持中文名，但**同名 NPC 会取第一个**。
3. **`give` 改存档**。不保存就退出无影响；保存了就真的挂上了，记得 `clear`。

## 结果出来后怎么用

- 若是 **A/B**（索引限制）：直接决定 `DungeonTrigger` 要写几行 → 进入建表阶段
- 若是 **C**（`addBattleUnit` 限制）：需要改用 `&` 索引语法，官方 `id=22201` 是范本
- 若**挂上了但一个都没上**：说明 `dungeonType` 不匹配（mod 只覆盖
  `10|11|20|30|39|47|48|49|50|52|54|55|58|73`），换个副本再试
