# 同一份正文多路到达 UI：判重必须问「屏幕真相」

> ⚠ **已归档**。本文是一次性排查记录，没有对应的现状文档，**日常开发不用看**。
>
> **结局**：改成按「屏幕真相」判重（谁真的画了这一帧），不再按数据来源猜。

---

**症状**：截图里两条 NPC 气泡**像素级完全相同**（8 行、每行宽度与居中位置逐项相等、行距 22px、
段间距 44px 一致、整体偏移正好 242px），上下相邻、中间没有任何行（无「行动记录」组、
无「内心思量」块、无「主动传音」分隔条）。

**判定"这两条泡是谁画的"用了三条证据**（这套读图法可复用）：
1. **像素全等 ⇒ 同一个字符串**。尾随换行会多出一行（9 个文字带）、首尾空格会挪动该行居中位置
   ——都没有，所以不是"内容相近的两段"，而是同一份文本渲染了两遍。
2. **两泡之间没有任何行 ⇒ 排除"模型复述"那条**（那一条必然夹着它的工具组/思考块）。
   ⚠️ **但不能据此断定"这一回合没调工具"**：工具组的插入位置取决于调用发生在哪一步 ——
   与正文同一步的调用，组排在正文泡**之后**；而"先查后答"的调用，组早就建好、排在正文泡**之前**。
   用户确认该回合**有**调用工具，组就在截图裁掉的顶部。
3. 排掉之后只剩两路：`step(text)` 与 `npc_reply`（见下）。

**根因**：终稿正文**两路到达** UI（① `step(text)` 每步正文 ② `npc_reply` 回合收口），
拦住后者重复渲染的唯一防线是一句**字符串比对**：

```csharp
if (fullText == _lastRenderText && _curTurn == _lastRenderTurn) return;   // 旧写法
```

它隐含一个错误等式：**「我记不记得画过」==「屏幕上有没有」**。而往屏幕上放正文的有**三条**路：

| 放正文的路 | 旧代码登记记账吗 |
|---|---|
| `FinishNpcBubble`（`step(text)` / `npc_reply`） | ✅ |
| `ReplaceHistory` 的 `AppendNpcStatic`（回放） | ❌ **漏的就是它** |
| 流式 `AppendDelta` | ❌（通常会被随后的 `step(text)` 覆盖并记账，无害） |

漏登记哪条，那句判据就在那条之后失效。两条**独立**成因都由此而来：

* **① 窗口 C（用户截图那条）**：`turn/end`（`dialogue_agent.py:653`）与 `npc_reply`
  （`ws_channel.py:601`）之间**隔着整个 `run_until_idle` 的 drain**（多回合 drain 时可达十几秒）。
  玩家见回合慢、以为卡了，**再点一次开窗**（`OpenFor → Open() → ResetContent()`，**不受 `_busy` 守卫**
  ——守卫只装在第二层 `OpenChatAndReplay` 上，而 `ResetContent` 在第一层就已执行完）：
  `ResetContent` 把记账清零（`_lastRenderTurn=-1`，而 `_curTurn` 被**刻意保留**），
  紧接着的回放**这次包含本回合**（`history.py:172` 只取**已闭合**回合，此时回合已闭合）
  → 把正文画了出来却无人登记 → `npc_reply` 判不出重复 → **再画一条**。
  ★ 反直觉点：**回放会不会画出这段正文，取决于重放发生在 `turn/end` 之前还是之后** ——
  之前不含（作者当年"清零"想保的正是这个场景：否则终稿会被误判重复而**整条吃掉**）、之后含。
  同一把"清零"的锤子，一个窗口下是对的，另一个窗口下就砸出重复。
* **② 模型复述（账本证据）**：`BOlQu6/赵勤.jsonl` 第 1 回合 step3/step4 携带**逐字节相同**的
  116 字正文（step3 还带一个工具调用）。流式门（`OnDeltaEvent → BeginNpcBubble`）**天生没有去重**
  （那时还不知道全文），于是下一步的重流又建了一条泡；而随后 `step(text)` 命中去重就 `return` 走了
  —— 那条泡留在屏幕上。

**修法（三条，都在 C#，Python 未动）**：

1. **`ReplaceHistory` 参与记账**：`case "assistant"` 渲染完把 `_lastRenderText/_lastRenderTurn/
   _lastRenderRow` 登记为"刚画的那一条"。两种次序自动各归各位（回放含本回合 → 末条属于本回合
   ⇒ 终稿跳过；不含 → 末条属于上一回合 ⇒ 终稿照常成泡）。
2. **判重命中时撤掉流式的重绘泡**（`DestroyActiveStreamingBubble`）—— 治成因②。
   能走到"判重命中"就说明这段正文已定稿，那条重绘泡一定是多余的。
3. **`FinishNpcBubble` 的"新建"收窄为最后一档**：判定抽成零 Unity 依赖的
   `UI/BubbleCommitPolicy.cs`，四档 **Skip / 覆盖流式泡 / 覆盖末行 / 新建**。
   中间那档治一个既有缺陷：`_collect_reply` 会剥 `<think>`、剥行首自名前缀、`strip`，
   而 `step(text)` 发的是原文 —— 两者不等时旧代码会**为这点差异新建一条泡**
   （同一段话说两遍），正确动作是**拿规范化后的终稿覆盖原来那条**。

**判重四条件（缺一不可，别顺手放宽）**：有正文 ∧ `curTurn > 0` ∧ 同回合 ∧ **末行仍在屏幕上** ∧ 文本逐字相同。
最后一条 `lastRowAlive` 是刻意的：把"画过"当成"屏幕上有"正是本 bug 的根源，所以坚持问屏幕 ——
行已不在时宁可按"没画过"处理（**丢失比重复严重得多**）。跨回合文本相同（模型复读）**必须**照常成泡。

**测试（两层，缺一不可）**：

| 层 | 位置 | 测什么 |
|---|---|---|
| C# 单测 | `csharp/tests/BubbleCommitPolicyTests`（net8.0 控制台，`dotnet run`） | 判定表 + 用"屏幕记账模拟器"喂帧序列断言**屏幕上剩几条泡**（10 个场景，25 项断言） |
| 源码契约 | `tests/test_bubble_dedup_contract.py`（pytest） | 真实 `ChatWindow.cs` 的**接线**：三条放正文的路都登记、判重命中撤重绘泡、`ResetContent` 不碰 `_curTurn`、策略类保持零 Unity 依赖、单测链接同一源文件 |

两边都做过**变异验证**（C# 5 项 / Python 7 项，逐条回退确认变红）——本仓库有过恒真断言的先例
（`[t["name"] for t in ALL_TOOL_SCHEMAS] == TOOL_ORDER` 左边由右边派生），新增测试不做变异验证不算数。

⚠️ **跑 C# 单测务必走 `scripts/dev/run_csharp_tests.py`**（它先清 `obj/bin`）：`dotnet run` 是增量构建，
变异验证在同一秒内反复改源码时，MSBuild 会因 mtime 落在同一刻度而判定"无需重编"→ 跑上一次的二进制
→ 拿到假绿/假红（第一次写变异脚本就踩到，表现为"还原源码后仍报同一批失败"）。

**已知未修**：多步回合 + 窗口 B（在 `turn/end` **之前**重开窗）会**静默丢失**重开前已渲染的中间正文
—— `ResetContent` 销毁了它们，而回放按设计不含未闭合回合，`npc_reply` 只带最后一步的正文且与末条泡
逐字相同（判重跳过）。修它要动"投影是否包含未闭合回合"或"历史区/直播区分离"，属结构性改动；
当前无实机实例，暂不做（`S10` 场景在 C# 单测里把现状固化成断言，改动了会立刻看到）。
