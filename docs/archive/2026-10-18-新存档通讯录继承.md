# 「新开一个存档，通讯录继承了」：身份帧允许为空，而空=沿用上一个存档

> ⚠ **已归档**。本文是一次性排查记录，没有对应的现状文档，**日常开发不用看**。
>
> **结局**：身份帧不再允许空值冒充「沿用上一个存档」。

---

**用户现场**：「由用户反应新开一个存档，也就是新建一个世界，通讯录里面的继承了？？？我记得不会的啊，
专门做过处理的，通讯录的应该是和世界挂钩的。」

**隔离机制没坏**：目录 = `storage/worlds/<world_id>/`，`world_id` = **玩家 unitID**（C# 在
`load_happened`/`save_happened` 携带）。本机实测两个存档各自独立、换档日志正常（`存档命名空间 → 唐炎/BOlQu6`）。

**坏在"钥匙的传递"**。三层：

1. **身份帧允许为空**：`EGameType.IntoWorld` 那一刻 `g.world.playerUnit` 可能还没挂上（世界正在重建），
   `FillWorldIdentity` 读不到就不写键。**本机日志实测：134 条 `world_hello` 里 67 条没有 `world_id`，
   其中 17 条是"人已经在世界里"却读不到**（10 次 BOlQu6、7 次 7tlNzH）—— 窗口真实且频繁。
2. **Python 对"空"的语义是"沿用"**：`_apply_world` 的 `if not wid: … 沿用当前存档命名空间; return False`。
   这条本来是救"Python 中途重启不许丢档"的命（D.24），但玩家从主菜单新建存档时它手上正是**上一个存档**
   的钥匙 ⇒ 新档读到旧档的通讯录，而且回包 `world_known=true`（Python 确实"定档"了，只是定在别人家）
   ⇒ C# 无从分辨 ⇒ 照单写进镜像；新档加的好友还会写进旧档目录。
3. **回包不带身份**：`list_contacts`/`list_sessions`/`list_hidden` 只回 `world_known`（D.24 补的那道闸
   只挡"Python **不知道**是哪个档"，没挡"Python 知道的是**另一个**档"）。一次跨档回包（面板刚开过 /
   连接正在更替）就能把旧档名单写进新档镜像。另外**没有任何"离开世界"的帧**（`Destroy()` 只停 WS），
   从回主菜单到新身份到达整段窗口都是旧档。

**修法（三条防线，缺一条都还能串；`tests/test_world_identity_failclosed.py` 17 项 + 变异 12 项钉住）**：

* **① Python：进世界帧宣告 `identity:"unknown"` ⇒ 作废身份**（`ChatHub._invalidate_world`：`world_id=None`
  → 闸门生效 → `list_*` 回空表 + `world_known=false` → C# 一个字都不写 → 面板如实提示"尚未取得存档身份"）。
  **"进世界"这件事本身就是"旧身份作废"的证据**，与能不能读到新身份无关。
  ⚠ 两处刻意的不对称，勿"统一"：`world_hello`（连接事件）读不到仍**沿用**（D.24 的救命绳）；
  `save_happened` 宣告 unknown 也**不作废**（存档不是"世界变了"的证据，作废会让 `flush_all` 整档跳过）；
  同一不对称在 C# 侧逐字对齐：`FillWorldIdentity(worldEvent, worldEntry)` 的 `worldEntry` **只**在
  `load_happened`/补发那一帧传（它是唯一清 `_expectedWorld` 基准的场合）——若 `save_happened` 也清，
  一次"存档那刻恰好读不到玩家单位"就会让此后所有回包被判废（面板一直说"尚未取得存档身份"、
  `list_sessions` 也刷不动），而 Python 那边一切正常。
* **② C#：`IntoWorld` 后逐帧重试补发**（`ModMain.StartIdentityRetry`）：读到身份就补发一帧 `load_happened`
  （幂等：第一次已丢弃过）+ 重拉三个名单。四条出口：读到 / `_worldEntrySeq` 变了（又换档）/ `Destroy()`
  帧回调随场景销毁 / 超时 60s（放弃也安全 —— Python 停在作废态，不会端出旧档数据）。
  为什么必须补：**新存档还没有存档文件**，`save_happened` 可能几分钟后才来，不补则整局看不到名单。
* **③ C#：换档先整表作废镜像再重拉**（`ContactDuty.ResetForWorld` → `ContactStore.ResetForWorld` 清
  `_manualNames/_manualUnitIds/_sessionsLast/_localLast/_hiddenNames` + `_manualLoaded=false`）：回包没回来
  之前面板会先把旧档名单渲染出来（`ContactPresenter.Show()` 第 ③ 步"先把 Store 里已有的镜像并进来"），
  "等回包覆盖"不够。**且每个回包按自带 `world_id` 判废**（`ContactDuty.WorldMatches`：与
  `FillWorldIdentity` 宣告的 `ExpectWorld` 基准不符 → `NoteStaleReply()` → 一个字节都不写；
  缺键 = 老 Python ⇒ 放行，向后兼容）。
* 顺手：换档/重连补 `ContactDuty.RequestHidden()`（原先只在面板打开时拉 ⇒ 隐藏名单跨档残留）、
  换档清 `UnreadStore` + HUD 角标。

**诚实边界**：本机日志里 17 次空身份**恰好**都跟在带 id 的 `load_happened` 后面（`load_happened` 缺 id
的次数为 0），所以本机没复现 —— 这就是用户说的"有时候"。报告者那台只要有一次落在
`load_happened` 上就必然串档。**洞④（代理键）未修**：`world_id = 玩家 unitID` 是代理键，本机存档槽 id
（`1_Fr17CF`/`4_uVUd4t`）与它并非一回事；若游戏会给新存档分到同一个 unitID，上面三条都救不了
（Python 没有任何信息能察觉"这是另一个世界"）——需另找"存档/世界级 id"。
