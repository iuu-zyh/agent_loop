# 群聊四件事：异常不静默 / 点名不预开泡 / 隐藏输入侧折叠 / 折叠带说话人

> ⚠ **已归档**。现状见 [`docs/features/group-chat.md`](../features/group-chat.md)。本文只保留当时的排查过程与被推翻的中间结论，**追溯「这个结论怎么来的」时才需要读**。
>
> **结局**：四条全按用户拍板落地。

---

**触发场景（用户实测截图 + 日志）**：新建群「与姜萌、濮阳彤萱的」→ 玩家发「有人吗？」→
姜萌**先冒出一条带头像的气泡**、随之显示她的「运行时上下文」与「内心思量 · 850 字」，
但她**一个字没说**；过了一会那条气泡**自己消失了**，然后是濮阳彤萱正常发言。
用户问："是因为她选择沉默吗？那不该第一时间就显示气泡。"

**先答"为什么"（排障结论，证据链完整）**：

| 事实 | 证据 |
|---|---|
| **不是沉默** | `agent_loop.log` 全文件里 `弃权` 出现 **0** 次（弃权路径有自己的 INFO 日志）；出现的是 `群 g2：姜萌 的回合异常（本轮跳过该成员，其余照常）` + `TimeoutError` traceback |
| **是流式请求被挂钟硬顶砍断** | `16:17:33 ERROR … 超过 45.0s 未完成（挂钟硬顶；对端心跳无法续命）｜已推送 token=382 已耗时=45.0s`；紧接着 `流式中断且已推送过 382 个 token，不重试（防重复展示）` |
| **那 850 字是"已推送的 382 个思考 token"** | `text_delta(part=think)` 不进 `Player.log`（只有 step 帧记），而 UI 上那块折叠正是她流的思考 |
| **气泡是被"下一个人的 speak"撤掉的** | Python 异常分支**一个帧都不发**；C# 那边只在 `ApplyRoomState(speak/silent/end)` 里撤空气泡 ⇒ 濮阳彤萱的 `speak`（16:17:33.7，紧接失败后 0.5s）顺手撤掉了它。整轮 C# 只有**一对** `忙 ON/OFF`（`SetBusy` 只在变化时打日志），与此吻合 |
| **她为什么没有「系统组装」而濮阳彤萱有** | 群标签/成员名单走 **L1 运行时上下文**（`format_l1_context`），不进 system 段 ⇒ 她的 sys 与上一轮单聊逐字相同、差分不发；濮阳彤萱是这局新建的活体 ⇒ 5 段全发。**不是丢帧** |

**四件改动（A/B/C2/E）**：

| 代号 | 改什么 | 为什么（症状 → 修法） |
|---|---|---|
| **A** | 成员级异常**当场发** `room_state(phase="error")`，带**人话**归因（`TimeoutError` → 「模型超时（未在时限内完成）」；★09-18 起按首字/停顿分型，见 docs/features/brain-liveness.md §4★，traceback 只进日志）；C# 撤空气泡/定稿半截正文 + 一行系统提示「姜萌 这次没能开口：…，本轮跳过」，**不复位忙碌态**；**全员都没开口**时终帧 `end` 的 `text` 再汇总一次（`if not spoken and errs`） | 异常分支原本只 `log.exception` + `continue` ⇒ 玩家**零解释**、空气泡挂到下一人开口。与 `silent` 分开是故意的：弃权是模型的选择，出错是我们的故障 |
| **B** | 群聊折叠标题带说话人：`姜萌 · 内心思量 · 850 字` / `姜萌 · 行动记录 (3)`（`ChatWindow.SpeakerLabel`，单聊恒为原标签） | 气泡不再预开之后，思考期间"谁在说"没有线索；且成员出错/弃权后剩下的 `内心思量 · 850 字` 是**无主内容**（用户原话"看着很诡异"） |
| **C2** | `speak` **不再预开气泡**；正文到了才起泡（流式 `ApplyDelta`、整段 `ApplyStep(step/text)`，两条路都补「名字：」+ 精确 unitID） | 点名就开泡 ⇒ 模型思考三四十秒期间挂一条空气泡，且弃权/出错时要等下一个人的 speak 才消失 |
| **E** | 群聊**不再渲染**「系统组装 / 运行时上下文」（`OnStepEvent` 里 `IsRoomMode` 早退）；**帧照发**（`NoteTurn` 必须排在早退之前，回合号是气泡去重判据） | 多聊时每个成员各来一套，一屏大半是这些块（用户："不美观，没有必要"）；它们本来就不进历史回放 ⇒ 去掉无缺口 |

| **F** | 每个成员边界（`speak` / `silent` / `error` / `end`）都调一次 `ChatWindow.FinishThink()` | 复核第二处：`FinishThink()` 全工程**只有单聊 `npc_reply` 那一处**调用过 ⇒ 群聊里思考折叠**从来不关**，下一位的思考增量并进上一位那块（实机：一块折叠 850 字，而 Python 日志显示那位**只推了 382 字**；标题还只写着第一个人的名字）。"出错"那条路尤其致命 —— 正常收尾时 `step(think)` 整段帧会顺手 `SetFull` 并关掉它，而超时/异常恰恰**没有那一帧** |

配套：`room_state` **每帧一行日志**（`群状态 speak 说话=姜萌 实例#4`）+ 忙标带理由
（`忙 ON 实例#4 ← 群点名 姜萌`）—— 这一族帧此前**零日志**，本次排查时 `Player.log` 里
连"谁被点名"都查不到，只能靠 Python 侧反推。
