# 气泡观感三件事：对齐装反 / 文字出框 / 空行太大

> ⚠ **已归档**。本文是一次性排查记录，没有对应的现状文档，**日常开发不用看**。
>
> **结局**：对齐、出框、行距三处都改了；「把截图当量具」的读图法记在这里。

---

**症状**（用户实机截图，单聊窗）：NPC 气泡里 22 字长行的**头一个字跑到白底外面**（压在透明的尾巴上）；
`)` 单独一行却贴到**最右边**、`见过道友。` 也靠右；行与行、段与段之间空得厉害。

**定位手段：把截图当量具。** 游戏 1920×1080、canvas scale = 1 ⇒ **1 UI 单位 = 1 px**，
于是"可见白底边界 / 文字 ink 边界 / 行距"都能直接量出来，再跟预制件字段逐个对账：

| 量到的 | 数值 | 对上哪条配置 |
|---|---|---|
| NPC 气泡 rect | x95..540（= 450 单位） | `NpcBubble.m_SizeDelta.x = 450` |
| 可见白底 | x129..540 | 图里 body 左内缩 35px（`npc气泡.png` 470 宽，body 从 x=35 起） |
| 最长一行（22 字） | 左端 x113~114 | 文本 rect 从 x107 起 + **右对齐** ⇒ 左端越过白底 **15~16px** |
| 行高 | 22px（fontSize 19 ⇒ 1.16em） | `m_FontData`：size 19 / lineSpacing 1 ⇒ **正常，不是行距设大了** |
| 气泡高 | 183 单位 = 8 个行位 | 其中 **2 个整行是空行**（正文里有 `\n\n`） |

**根因（三条，互不相关）**

① **NPC 侧正文对齐错了**：`NpcBubble/Text` = `m_Alignment: 2`（UpperRight）—— NPC 文字右对齐，
   于是长行左端伸到文本框外、短行（`)`、`见过道友。`）贴右边缘。`UserBubble/Text` 当时是 `0`（左对齐），
   **本来就是对的**。（"格式看着不对"的直接原因。）

   ⚠ **第一版判断错了一半**：我把它写成"两边装反了"，顺手把玩家侧改成 `2` + `MiddleRight` —— 实机被
     用户打回："玩家气泡应该**左对齐 + 顶部**"。真因：气泡在窗口里的左右位置是**行模板
     `HorizontalLayoutGroup`（childAlignment 3 / 5）**决定的，**与文字对齐无关**；本工程气泡是
     **固定 450 宽**、文字只占其中一段，右对齐会让短句浮在气泡中间偏右（那张 `[2年8月3日] 你还认识我吗?`
     的截图就是）。**最终：两侧正文都是 `UpperLeft` + 子项 `UpperLeft`（贴顶）。**
② **内边距没算"尾巴内缩"**：两张气泡图把尾巴画在**图片包围盒里面**（NPC 左 7.4%、玩家右 7.0%），
   Image 又是整张图铺满 450 宽的 rect ⇒ 可见白底只有 `x∈[33.5, 448]`，而两个气泡的 VLG padding 都是 **12**
   ⇒ 靠尾巴那侧的文字有 ~20 单位画在白底外。**不报错、不裁剪，只是"文字溢出了气泡图"**。
③ **正文里的空行**：模型自发用 `\n\n` 分段，而 uGUI `Text` 没有段间距概念 —— 一个空行 = **一整行行高**
   （fontSize 19 ≈ 23 单位），于是 1/4 的气泡高度是纯空白。

**修法（两批，互不依赖）**

*第一批 · 预制件（要重打 AB）* —— `scripts/dev/prefab_patch_chat_bubble_style.py`（幂等，改前自动 `.bak_bubblelayout`）：

- `NpcBubble/Text` 2→0（NPC 侧改左对齐）；`UserBubble/Text` **保持 0**；两侧子项对齐都保持 `0`（贴顶）
  —— 第一版曾把玩家侧改成 `2`+`MiddleRight`，实机纠正后回退（见 ① 的说明）
- padding：NPC `(L40, R14, T12, B12)`、玩家 `(L14, R40, T12, B12)`（尾巴侧 40 > 图里内缩 35/33 + 余量 4）
- VLG `m_ChildAlignment` **保持 0**（UpperLeft：文字贴顶）。第一版试过 3/5 让单行泡垂直居中，被用户打回
- **宽度 450 不动**（用户拍板）：代价是文字区 426→396，每行 22→20 字 —— 换来每个字都在白底里
- verify 里额外卡两条**静默坑**：`LayoutElement.m_LayoutPriority` 必须 = 0（与 VLG **同优先级**才"取大者"；
  = 1 会让 LayoutElement 独占 preferredHeight ⇒ 长文本气泡**恒 76 高**、被 `vOverflow=Truncate` **静默截掉**）；
  两个气泡的对齐必须**相反**（相同 = 又装反了）

*第一批的**第二条腿**（运行期兜底，不用重打 AB，重启即生效）*：`ChatWindow.ApplyBubbleTextLayoutFloor()`
在 `Init` 里按**下限**把两个气泡模板的正文对齐拉回 `UpperLeft`、padding 抬到 `≥40/14/12`
（只抬高不缩小 ⇒ 预制件配得更大就听预制件的）。照抄 `ApplyScrollSensitivityFloor` 的"两条腿"约定：
预制件是真源、C# 兜住手上这份老 AB。两侧常量由 `tests/test_chat_bubble_layout_contract.py`
逐项对账，**不许与补丁脚本漂移**（漂移的症状是"重打 AB 前后观感不一样"）。

*第二批 · 显示层（不用重打 AB，重启即生效）* —— `csharp/BubbleTextCore.cs` 的 `Tighten`：
折叠空行 + 逐行 trim + `\r\n` 归一，落在**四个写泡点**（流式 `LateUpdate` / 终稿 `OverwriteStreaming` /
行覆盖 `SetRowText` / 新建 `ChatBubble.SetText`）。**为什么放显示层而不是改提示词**：正文来源有六条
（单聊终稿、群聊 `room_say`、流式 delta、历史重放、玩家输入、`/compact` 提示），只有收口到一处才不会有
"某条路还是大空行"；而且**流式与终稿必须给同样的观感**，否则定稿那一瞬间屏幕会跳一下。

**第三批（用户 09-17 拍板：不做）· 气泡图的 9 宫格 —— 一个反直觉的发现**

两张图的 `spriteBorder` 只设了尾巴那一侧（npc `{x:38,y:0,z:0,w:0}`、玩家 `{x:0,y:0,z:33,w:0}`），
上下边 = 0 ⇒ 尾巴与圆角随气泡高度被纵向拉伸。想"钉住"就得把尾巴整段包进下边距（npc `bottom ≥ 88`，
尾巴占 sprite y42..88）。**但是**：`Image` 在 Sliced 模式下的 `preferredHeight` = `GetMinSize().y`
= **上下边距之和**，而它与 VLG、LayoutElement **同优先级取大者** ⇒ 设了边距就等于给所有气泡加了
`88/93` 的**最小高度**（单行泡 76 → 88/93，+16%/+22%），而且短气泡上原生尺寸的尾巴会占掉一半高度。
**所以这不是白捡的改进**：真要做得好，得把尾巴重画到图片最底部（`bottom≈30 / top≈30` ⇒ 边距和 60 < 76，
最小高度不变、圆角与尾巴还都是原尺寸）。三选一摆给用户后结论是**"不做"**：尾巴/圆角继续随高度等比缩放
（尾巴始终指着头像那一侧），换来单行泡维持 76 的紧凑高度。
⇒ **这不是漏做，是拍板不做**。将来真要动，按第三种（重画尾巴到图片底部）做才划算 —— 直接改 meta 会让
所有单行气泡长高 16%~22%。

**测试与变异**

- `tests/test_chat_bubble_layout_contract.py`（10 项）：常量自洽（两侧都 `UpperLeft`）/ **真 prefab 回读** /
  幂等 / 每行字数区间（16~24 字）/ **真 PNG 量出的内缩 vs 真 prefab 里的 padding** / 宽度冻结 /
  **C# 兜底那条腿的常量与补丁脚本逐项相等** / 兜底真的接在 `Init` 上且纠正方向是 `UpperLeft`
- `tests/test_bubble_text_contract.py`（8 项）：核存在且**零 Unity 依赖** / csproj 登记 /
  测试工程链接**同一份源文件** / 四个写泡点各一条 / 一条"全仓扫描有没有漏整形的新分支"
- `csharp/tests/BubbleTextTests`（**48 项断言**）：空行折叠、`\r\n` 归一、全角/不换行空格、
  **不该动的东西**（单换行=分段、行内空格、富文本标签、名字前缀）、null 与幂等、真机样本逐字对照
- 变异 **30 项全部捕获**（`scripts/dev/mutate_check_bubble_style.py`：资产与接线 20 + 折叠规则 10），
  其中"玩家正文改回右对齐 / 玩家子项对齐改成居中 / C# 兜底常量漂移 / 兜底没接线 / 兜底方向写反"
  五条就是这次实机事故的**回归护栏**

第一次跑漏了 **3 项**，两条是测试自己不够狠、一条是脚本自己的错：① 深度检查（PNG 内缩）当时比的是
**补丁脚本的常量**而不是**真 prefab 的字段** ⇒ 直接改资产它照样绿（改成读 prefab 之后，变异①②当场变红；
这条同时守住了"有人手改预制件 / Unity 里又存了一次"这种漂移）；② 变异脚本里 `m_LayoutPriority`
的缩进写成 4 空格（实际 2 空格）导致变异**施加不上** —— 脚本如实报 ✗ 而不是假绿，这正是"变异施加失败
必须算失败"的价值。
