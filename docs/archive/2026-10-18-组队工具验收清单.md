## 二、现在就能做的唯一一件事 —— 而且**必须现在做**

### 问题：`addBattleNPCData` 的索引 `0` 是「第一个」还是「全部」？

这是我们设计里**最大的未证假设**。我们的 `DungeonTrigger MID&001` 用的是三对配对写法：

```
addBattleNPCData_MID&003_0 | addBattleUnit_MID&003_-1_10_2_1_2_0
addBattleNPCData_MID&003_1 | addBattleUnit_MID&003_-1_8_2_1_2_0
addBattleNPCData_MID&003_2 | addBattleUnit_MID&003_-1_6_2_1_2_0
setBattleData_alTeamIn_ok
```

- 若索引 `0/1/2` = 第 1/2/3 个抓到的 NPC → 正好 3 人 ✅
- 若索引 `0` = 全部 → 第一对就把 3 人全拉进来，后两对再各拉一遍 → **重复刷 / 超员** ❌

官方文档在这里自相矛盾：`addBattleNPCData` 正文写「加入**第一个**」，而 `npcConditionIndex` /
`conditionUnitDistance` 的说明写「单位索引 **1-5**，0-所有」。静态分析到此为止，只能实测。

### 为什么必须「部署前」做

这个实验借的是**已部署的 `TeamMultiProbe` + 工坊组队 mod 的表**（它的 `MID&003` 是与我们同构的
`feature_1_MID&51`）。探针按**名字**反查「结伴而行」——我们的 `RoleCreateFeature.json` 一进游戏，
反查就可能先命中我们自己的 ID，实验对象就换了。**现在游戏目录里只有工坊那份，是最干净的对照组。**

### 操作（约 5 分钟，心跳模式，中途不用重启游戏）

1. 启动游戏，进存档，**进世界**。
2. 建开关文件：

   `E:\SteamLibrary\steamapps\common\鬼谷八荒\ModExportData\Mod_Jgmg5L\_diag_team_multi.txt`

   ```
   action=givemap
   max=3
   radius=1
   ```
3. 等 ~2 秒，读 `Mod_Jgmg5L\logs\team_multi_summary.txt`，确认「已挂载 = 3」
   （若为 0，把 `radius` 加大到 5、10 再试）。
4. 把开关文件**改成一行**（改 mtime 即重新生效，不用重启）：

   ```
   action=dumpbattle
   ```
5. 进一个**普通战斗副本**（`DungeonTrigger MID&001` 的条件里有 `dungeonId` 白名单，普通秘境即可）。
6. 关游戏，读 `logs\team_multi_summary.txt`（结论）+ `logs\team_multi.log`（明细）。

### 判据

| 观察到 | 含义 | 我们要改成 |
|---|---|---|
| **1 个**队友上场 | 索引 `0` = 第一个 → 0/1/2 写法方向正确 | 仍需部署后确认 `1`/`2` 能否拉到第 2、3 个 |
| **3 个**全上 | 索引 `0` = 全部 → 三对会重复拉 | 只留一对 `_0_`，删掉后两对 |
| **0 个** | 条件没匹配（副本类型 / `dungeonId` 不在白名单） | 换副本；先用 `action=scan` 确认在场 NPC 身上真有「结伴而行」 |
| **超过 3 个** | 既重复又超员 | 只留一对 `_0_`，并在 C# 侧二次校验 |

> 这一步验的是**引擎语义**，不能验我们自己的表。但它能一票否决上面那套三对写法，
> 是这个项目里性价比最高的 5 分钟。

## 三、部署之后要验的（按重要性排序）

前置：DLL + exe + 8 张表都进 `E:\...\ModExportData\Mod_Jgmg5L\`，游戏重启。

### V1 · 工具能被模型调出来 ｜ 1 分钟
- 跟任意 NPC 对话，说「跟我一起下个副本吧」。
- **通过**：MelonLoader 日志出现 `team` 调用；弹出确认窗，正文
  「X想与你结伴同行，日后同闯秘境，可好？」，按钮「同意 / 不了」。
- **失败分流**：
  - 模型压根没提这个工具 → **schema 没进 exe**（回去查 exe 时间戳）；
  - 调了但不弹窗 → 查 `DramaDialogue MID&180` / `DramaOptions MID&181,182` / 对应 LocalText，
    看是否 120 秒 `DramaGate` 超时。

### V2 · 队友标记落在谁身上 ｜ 30 秒
- 同意后看气运：**`结伴而行` 应该在 NPC 身上**，玩家自己应该是 **`组队中`**。
- ⚠ **一票否决判据：玩家身上出现 `结伴而行`** → 玩家会被当成容器成员一起刷上台。

### V3 · 动态描述 ｜ 30 秒（含一次增量刷新）
- NPC 的「结伴而行」描述里应出现**你的名字**；
- 玩家的「组队中」描述里应列出队友名单；
- **再拉第二个人 → 玩家描述里的名单要在 ~5 秒内自己多出一个**（验证 `Tick` 监听）。
- 失败：描述是占位符 / 空白 → `allText` 键没命中（4 种语言只写一种，非中文界面会露馅）。

### V4 · 三人上限 ｜ 1 分钟
- 连拉 3 个，第 4 个必须被拒，提示队伍已满。
- 顺便验重复邀请：对已在队里的人再 invite → 应回「已经在队里」，不该重复挂气运。

### V5 · 副本里到底上几个人 ｜ 5 分钟 ★最重要★
- 带 2~3 个队友进副本，**数站场友军数量**。
- 这是第二节结论的落地验证。若不符，退路见第四节。

### V6 · 重伤 4 个月 ｜ 5 分钟
- 让一个队友在副本里**被打倒**，退出副本，查该 NPC 气运。
- **通过**：拿到 `内外重伤`，**剩余 4 个月**，血 / 灵 / 攻 / 防四项下降。
- **附带确认**：`-30` 到底是 **-30%** 还是 **-30 点**（表里写的是 `_0_-30`，
  `docs/archive/2026-10-17-组队配置表与部署.md` 按 -30% 记的，需在属性面板对一次数）。
- 失败：队友倒了但没上气运 → 链路
  `DungeonTrigger(triggerType=14, 1000ms)` → `unitAddEffect_<cond>_<BattleEffect>`
  → `BattleEffect 6009` → `DramaDialogue 190` → `addNPCLuck_1_MID&52` 某处断了。
- **已知风险**：`triggerType=14` 是**轮询**，可能在死亡那一帧之后就轮不到目标。若真断了，
  改成 Harmony 挂死亡事件直接上气运。

### V7 · 解散 + 扣好感（单边） ｜ 2 分钟
- 先记下该 NPC **对你的好感数值**（笔算，别只看提示）。
- `dismiss` 该 NPC → 同意。
- **通过需三条同时成立**：
  1. 好感 **-6 ~ -10**（随机，引擎再按当前好感档位折算）；
  2. **掉的是「他对你」那一条，「你对他」不变**（单边）；
  3. `结伴而行` 从他身上消失，玩家「组队中」名单少一个。
- 失败：好感没动 → 查 `ApplyIntim` 的 `clamp` 参数与 `AddIntim` 方向。

### V8 · 解散整队 ｜ 1 分钟
- `dismiss` 不填 target → 窗文案「要解散队伍、就此别过吗？」/ 按钮「就此别过 / 再想想」。
- **通过**：**每个**队友都掉好感、气运都清掉、玩家 `组队中` 消失。

### V9 · 重开 / 读档 ｜ 1 分钟 ★已知坑★
- 存档 → 退出 → 重进世界。
- **通过**：描述文字仍然正确。
- **为什么必验**：`g.conf.localText.allText` 在重载世界时会**重新初始化**，而成员签名不变
  ⇒ 若 `ResetTickState` 没生效，描述会退回默认文本且**再也不会刷新**。

### V10 · status ｜ 10 秒
- `status` 不弹窗，直接列出队友；重伤中的要标「重伤中」。
