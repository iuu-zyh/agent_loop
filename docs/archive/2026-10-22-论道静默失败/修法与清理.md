## 1. 结论速览

**一句话**：**传送把 NPC 当月的行动预算扣光了，导致他付不起论道所需的 5 天。**

问题不在论道，在传送。三层因果：

| # | 环节 | 事实 |
|---|---|---|
| ① | **传送实现用错了 API** | `movement:teleport` / `summon` 用的是 `UnitActionMoveNPC` / `UnitActionMovePlayer`（**走路**动作） |
| ② | **走路动作按距离收天数，且瞬移分支也不免** | `Init` 按两点距离算 `day`（61 格 ⇒ **15 天**）；`Create` **只看 `day > 0` 就扣**，不管 `OnCreate` 走的是瞬移还是真赶路 |
| ③ | **论道准入检查天数不够** | `Discovery.IsCreate` → `IsDayCost(costDay=5)` 对比 `residueDay`；已被扣成 0 ⇒ 返回 `1` ⇒ 拒绝。而 `ActionStart` **丢弃这个返回码** ⇒ 无 UI、无提示 |

**为什么手动点击能成**：两条路径的 `action.unit` 不是同一个单位——

| 路径 | 入口 | `action.unit` | 查谁的天数 |
|---|---|---|---|
| 面板手动 | `UINPCInfoUnitInfo.<InitMeum>b__19` @0x33601DE → `player.CreateAction(...)` | **玩家** | 玩家的（够 ⇒ 放行） |
| 工具调用 | `WorldUnitAIAction1037::ActionStart` @0x1845e22ee → `npc.CreateAction(...)` | **NPC** | 江宇文的（被扣光 ⇒ 拒） |

## 2. 关键机制（反汇编实证，均已真机验证）

### 2.1 `ActionStart` 丢弃返回码 —— 静默的唯一来源

```asm
; WorldUnitAIAction1037::ActionStart @0x45E2210
1845e22c5: call WorldUnitAITool::MovePoint(npc, toUnit)      ; ① 走过去
1845e22ca: test al,al
1845e22cc: je   0x1845e238a                                  ; false → onEndCall(false)
1845e22ee: call UnitActionRoleDiscovery::.ctor(toUnit)        ; ② 造论道动作
1845e2340: call [r9+0x1c8]                                   ; ③ 挂我们的 onEndCall
1845e236a: call [rax+0x1c8]                                  ; ④ npc.CreateAction(discovery)
1845e2370: ... 直接 ret                                       ; ★ ⑤ 返回码完全不看
```

**第 ⑤ 步是关键**：`CreateAction` 返回 1 时引擎毫无反应，只有 ③ 挂的 `onEndCall` 被调成 `false`。

### 2.2 `Discovery.IsCreate` 的两道关卡（顺序要紧）

```asm
; UnitActionRoleDiscovery::IsCreate @0x3F1A070
183f1a0b7: call UnitActionRoleToUnitBase::IsCreate   ; 剧情包 / 恶魔
183f1a0c0: jne  0x183f1a15f                          ; 非 0 → 原样返回（含 100）

; ② 天数关卡（isCostDay 恒为 true，见下）
183f1a0c6: cmp  BYTE PTR [rbx+0xaa],al               ; isCostDay
183f1a0cc: je   0x183f1a117
183f1a0f6: call ConfRoleDiscoveryBase::get_costDay   ; 配置表 "5"
183f1a100: call System.Int32::Parse                  ; → 5
183f1a10d: call UnitActionBase::IsDayCost            ; ★ 本次真机返回 1
183f1a114: cmovne edi,eax                            ; edi = 1

; ③ 禁令关卡（本次没走到，edi 已非零）
183f1a117: ...
183f1a125: call WorldUnitEffectSpecialBannedFunc::ActionFunc
183f1a154: mov  edi, 3                               ; 命中才返回 3

; ④ 统一出口
183f1a172: mov  eax,edi
```

**关键**：第 ② 道先跑。`edi` 一旦被 `cmovne` 置成 1，第 ③ 道只是"再确认一次"，
最后从 `0x183f1a15f` 直接返回 `edi`（=1）。

`isCostDay`（`+0xaa`）**恒为 true** —— `UnitActionRoleDiscovery::.ctor` 写死：

```asm
183f1acac: mov WORD PTR [rbx+0xa9], 0x101     ; +0xA9=isAward=1 ; +0xAA=isCostDay=1
```

### 2.3 `IsDayCost` 真正比的是什么

```asm
; UnitActionBase::IsDayCost @0x35083E0
183508410: mov  rsi,[rbx+0x10]                 ; rsi = action.unit
183508431: cmp  rsi,[rax+0x10]                 ; action.unit == world.playerUnit ?
183508439: je   0x183508498                    ; 相等 → 玩家分支

; 【NPC 分支】residueDay < day 直接拒
183508451: cmp  DWORD PTR [rax+0x38],edi       ; +0x38 = unitData.residueDay
183508454: jl   0x183508501                    ; → return 1

; 【玩家分支】residue > 0 或 day<=0 才继续细判
1835084a6: mov  eax,[rax+0x38]
1835084a9: test eax,eax
1835084ab: jg   0x1835084b1
1835084b7: cmp  eax,edi                        ; residue >= day ?
1835084b9: jge  0x183508486                    ; → return 0 放行
```

**两条分支逻辑相反**，这是「手动能成、工具不能成」的完整解释。

### 2.4 `day` 与 `residueDay` 是两套完全不同的东西

| | 位置 | 含义 |
|---|---|---|
| `WorldRunMgr.roundDay / roundMonth` | `WorldMgr` +0x20 → `run` | **世界时间**（你看到的"12月1日"），全局唯一 |
| `UnitInfoData.residueDay` | `UnitInfoData` +0x38，**每个单位各一份** | 该单位**当月可用行动力**，按月满值刷新 |

`WorldRunMgr::AddDay` @0x182A25400 只做 `add [rbx+0x10],edi`，**不碰任何单位的 `residueDay`**。
两者独立。

### 2.5 扣与还的时机（容易搞错，这里钉死）

| 动作 | `action.day` | 扣款时机 |
|---|---|---|
| **传送**（旧）`UnitActionMoveNPC` / `MovePlayer` | 按距离算（61 格 ⇒ 15） | **创建时**（`Create` 见 `day>0` 就扣），且**永不退还** |
| **论道** `UnitActionRoleDiscovery` | **恒 0**（`Init` 没设过 `day`） | **完成时**（`DiscoveryEnd` 里 `AddResidueDay(costDay)`） |
| 论道失败 | — | **不扣**（`DiscoveryEnd` 从未执行，`Create` 那步 `day=0` 也没扣） |

```asm
; UnitActionRoleDiscovery::DiscoveryEnd @0x3F186D0 —— 是【扣】不是退
183F18831: cmp  byte [rsi+0AAh],0        ; isCostDay
183F18838: je   跳过
call ConfRoleDiscoveryBase::get_costDay
call System.Int32::Parse                  ; eax = 5（正数，没 neg）
mov  edx,eax
call WorldUnitBase::AddResidueDay         ; → sub [unitData+0x38], 5
```

`WorldUnitBase::AddResidueDay` @0x1832B8850 第一条就是 `sub [rax+0x38],edx`
（内部夹到 0，不会为负）。**所以论道成功 = 推进 5 天，符合游戏设计。**

## 3. 修复

### 3.1 改了什么

`csharp/tools/ToolExecutor.cs` 的 `Movement()`：

| op | 旧 | 新 |
|---|---|---|
| `teleport`（NPC→玩家） | `new UnitActionMoveNPC(dest)` + `CreateAction` | `new UnitActionSetPoint(dest)` + `CreateAction` |
| `summon`（玩家→NPC） | `UnitActionMovePlayer` / `UnitActionMoveNPC` | `new UnitActionSetPoint(destPt)` + `CreateAction` |
| `travel`（NPC 自主去城镇） | `UnitActionMoveNPC` | **保持不变**（真赶路，扣天数合理） |

### 3.2 为什么是 `UnitActionSetPoint`

反汇编事实（`F:\_dt_dump\types\UnitActionSetPoint.txt`）：

| 特性 | `UnitActionSetPoint` | `UnitActionMoveNPC` / `MovePlayer` |
|---|---|---|
| 覆盖 `Init` | **没有**（方法表只有 `.cctor/.ctor/IsCreate/OnCreate/UpdateGimpedPoint`） | 有，会算 `day` |
| `day` | **恒 0**（基类默认） | 按距离算 |
| `Create` 扣费 | `jle` 直接跳过 ⇒ **不扣** | 扣 |
| 坐标 + 格子索引 | `OnCreate` 内 `call UnitInfoData::SetPoint` | `OnCreate` 内 |
| 业务校验 | **有 `IsCreate`，12 条门槛** | 有，但门槛不同 |

`UnitInfoData::SetPoint` @0x2FC32E0 自维护格子索引：

```asm
call WorldUnitMgr::GetUnit
call Map::DelGridUnit(旧点, unitID)     ; @0x3CE5F40
mov  [rdi+0x28], pointX                 ; +0x28
mov  [rdi+0x2C], pointY                 ; +0x2C
mov  byte [rdi+0x138], 1                ; 标记已移动
call Map::AddGridUnit(新点, unitID)     ; @0x3CE5590
ret                                      ; ★ 全程不碰 residueDay
```

⇒ **这就是引擎自己的"零成本瞬移"**：`day=0` + 维护格子表 + 有业务校验。
比裸调 `SetPoint` 更安全（非法落点会被 `IsCreate` 挡掉并给出码）。

### 3.3 附带的四道保险

```csharp
var mvSet = new UnitActionSetPoint(dest);
int setRet = wub.CreateAction(mvSet, true);
if (setRet != 0) → 报出具体码（NativeRefuseWhy），不谎报成功

int residueBefore/After = ...residueDay;          // ① 天数前后对比
int nx/ny = ...pointX/pointY;                     // ② 回读坐标复核
if (nx != dest.x || ny != dest.y) → Fail(...)     //    不到位就报错
ModMain.P("... residueDay " + before + "→" + after
          + (before == after ? "（未扣天数 ✓）" : "（★ 天数被改了，异常）"));   // ③ 日志自证
["day_cost"] = before - after                     // ④ 返回值带实际消耗，模型可见
```

## 5. 踩坑记录（★ 最省时间的部分 ★）

排查绕了七圈，**每次都是拿推理当证据**。列出最容易重犯的几条：

| # | 错误结论 | 为什么错 |
|---|---|---|
| 1 | "`Create` 没跑，因为没有 `Create` 调用栈" | `Create` 按 `day` 分叉，`day<=0` 不打栈。那个"8 次 vs 0 次"是**假对照** |
| 2 | "`IsCreate` 拒了" | 探针一装：两层 `IsCreate` 全 `code=0` |
| 3 | "`isCreateCall=True` 说明对象被复用" | 它是 `IsCreate` **自己**置的（`mov BYTE [rbx+0x28],1`），Postfix 必然读到 |
| 4 | "`ActionStart` 返回值完全由 `MovePoint` 决定" | **漏了出口 B**（`CreateAction` 的返回码被丢弃） |
| 5 | "`ok=False` 只是中间阶段" | 用户当面质疑；它是**真实失败** |
| 6 | "`CreateAction` 拦不到虚表分发" | 探针自己写错（`as` 转型失败静默 `return`） |
| 7 | **"`day=0` 说明 day 层已排除，码只可能是 3"** | **三重错误**：① 把 `act.day` 与 `conf.costDay` 当成同一个量；② 漏了 `cmovne edi,eax` 后禁令段不再生效；③ 没核对 `IsDayCost` 读的是 `action.unit` 的天数，而两条路径的 `action.unit` 是不同的人 |

## 8. 一句话留给后来者

**论道本身没问题，是"走过去"这件事把 NPC 的当月行动力花光了。**

更普适的教训：
- 引擎里"看起来像瞬移"的分支（`moveComplete=true`、坐标立刻变）**不代表不收钱**——
  收费判定在 `Create`，只看 `action.day > 0`，与 `OnCreate` 走哪条分支无关；
- 排查"静默失败"时，**先找那个"没人接收的返回值"**（本案 `ActionStart` 丢弃 `CreateAction` 的码）；
- **同名变量在不同类里可能是完全不同的东西**（`action.day` vs `conf.costDay`），
  以「谁传参」为锚，不能以变量名为锚。
