# 提示词「重置为默认」+ 一个被它顺带揪出的换行膨胀 bug

> ⚠ **已归档**。本文是一次性排查记录，没有对应的现状文档，**日常开发不用看**。
>
> **结局**：「默认内容」唯一来源定为 exe 内置副本；换行膨胀一并修掉。

---

**需求**：提示词页加一个按钮，把**选中的文件**一键还原成出厂内容。

**① 「默认内容」的唯一正确来源 = exe 内置副本**（这是整个功能唯一一处"做错了界面上看不出来"的地方）

`prompts/` 有两份物理拷贝，别混：

| | 位置 | 谁动得了 | 用途 |
|---|---|---|---|
| **用户副本** | `<Mod根>\ModAssets\prompts\` | 玩家随时改（面板/记事本） | `paths.prompts_root()`：面板读写 + SystemPrompt 加载 |
| **内置副本** | `AgentLoopServer.exe` **文件内部**（打包时塞进的 `agent_loop/prompts/`） | 谁也动不了 | `paths.bundled_prompts_root()`：**只作重置来源** |

运行期实测（拿**已部署的 exe** 跑 `--selftest`，`AGENT_LOOP_DATA` 指到不存在的目录强制走兜底）：

```
[selftest] prompts(用户可编辑)=…\ModAssets\prompts
[selftest] prompts(内置默认)  =C:\Users\<用户名>\AppData\Local\Temp\onefile_31932_…\agent_loop\prompts
```

即 exe 每次启动把自己解压到 `%TEMP%\onefile_<pid>_<随机>`，里面带着**从未被玩家碰过**的原文，
进程退出即删、下次启动又是全新一份。这条兜底本来就有（`build_exe_nuitka.py` 的 `DATA_DIRS` /
`AgentLoopServer.spec` 的 `datas`，本意是"玩家把 prompts 删了 exe 还能起来"），重置只是把它**当数据源**用。

⚠ 铁律：`bundled_prompts_root()` **绝不回退**到 `data_root()/prompts`。真回退了，重置就退化成
"拿用户文件覆盖用户文件"，界面完全正常却永远无效 —— 实测这条变异（把默认源换成 `prompts_root()`）
只有靠**不传 `defaults` 参数**的测试才抓得住（第一版测试显式传了 `defaults`，等于替被测代码兜了底，
变异①⑩双双漏网 → 改成 monkeypatch 两个根 + 走生产形态）。

**② 白名单：不套 `_allow_create`，真正的闸门是"内置副本里有没有这个文件"**

| 文件 | `deletable` | `resettable` |
|---|---|---|
| `sections/*`（全局设定） | false | **true**（不许新建，但正是最需要"改坏能救回"的） |
| `personas/default.txt` / `_suffix.txt` / `compaction/default.md` | false | **true** |
| 玩家新建的 `personas/{npc}.txt` / `traits/*.json` / `compaction/{npc}.md` | true | false（没有出厂版本 → 拒绝，引导去用「删除文件」） |
| 虚拟条目 `config:player.persona`（自我人设） | false | true（"默认"= 空；C# 走 `set_config`，**不发** `reset_prompt`） |

两个标记语义正交（sections 是"不可删但可重置"），UI 据此预判、接口内部仍 fail-closed 把关。
`reset_prompt(rel)` **不收 text 参数**（结构上不可能变成往 sections 写任意内容的旁路），
来源用 `_resolve(rel, defaults, must_exist=True)` 复用同一套路径防护 —— 没写一行新的路径逻辑。

**③ 顺带揪出的真 bug：提示词文件的读写换行不对称**（不修的话重置会被下一次保存重新污染）

`prompt_files` 读用 `textio.read_text`（`read_bytes()`+decode，**不做换行翻译**），
写用 `Path.write_text(encoding="utf-8")`（Windows 上 text 模式**把 `\n` 翻成 `\r\n`**）→
一份 CRLF 文件每"读→写"一次多一层 `\r`。Windows 侧 python 实测：

```
第1次 13 字节  第2次 15  第3次 17  第4次 19        ← 每存一次多一层 \r
```

**而且不需要编辑**：`SavePromptFile` 提交的是**全量 `_promptCache`**，而 `SelectFile` 一读就把原文
塞进缓存 → "点一下文件 + 点保存"就给 CRLF 文件多塞一层。真机 8 个文件已有 4 个是 CRLF
（其中 `ModAssets\prompts\compaction\default.md` 是**旧版本**内容，md5 `20cb7ce5` vs 内置 `bd49c453`，
它同时是"重置"最好的实机样本）。只有 `prompt_files` 这 3 处写盘点受影响
（`config_store` / `contacts_store` 走 `json.dumps`，字典往返天然幂等）。

修法两条独立不变量，各自有测试与变异盯着：
- **读侧归一**：`read_text` 解码后 `\r\n|\r` → `\n`（与 `Path.read_text()` 的通用换行同语义；
  顺序不能反，反了会把 `\r\n` 拆成两个 `\n`）；
- **写侧不翻译**：新增 `textio.write_text`，`open(..., newline="")`，UTF-8 无 BOM → 读写成为不动点，
  `prompts/` 单调收敛到 LF。仓库里本来就是 CRLF 的 3 个文件（`world_basis.txt` /
  `world_persona_rules.txt` / `_suffix.txt`）一并归一，并加不变量测试
  `test_shipped_prompts_are_lf_utf8_no_bom`（内置那份要是 CRLF，"重置后再重置"会永远判 `changed=True`，
  幂等性就没了）。
  ⚠ 变异验证注意：`newline=""` 改回默认在 **Linux 上没有任何效果**（`os.linesep` 就是 `\n`），
  所以那条变异写成 `newline="\r\n"`（= Windows 上的默认行为），才能在任何平台上验出红。

**④ 幂等与生效**：目标字节 == 内置字节 → **不写盘**，回 `changed:false`（避免无谓触发 SystemPrompt
重组装）。`SystemPrompt._refresh_global_sections_if_changed` 是**按内容**比对（不是 mtime），
每个 step 的 `assemble` 前跑一次，persona 侧同样每步自检 → "下个回合生效"是保守说法，**下一步就换纸**。
Dev 布局下两个副本同体（源码树里那份 prompts/ 本身就是出厂真相）→ 如实回 `changed:false` + `note`，
不当错误。

**⑤ UI：预制件补节点（走 AB 资产固化），不做运行期克隆**

三个动作键原本是 `Save(0..0.5) / New(0.5..0.75) / Delete(0.75..1)`（保存键独占左半是因为
「保存文件（下回合生效）」在 15 号字下要 ~180px）。新按钮插在新建与删除之间，右半三等分：

```
Save 0..0.5 | New 0.5..2/3 | Reset 2/3..5/6 | Delete 5/6..1
```

`ThirdOfRight` 是"右半的三分之一"= **全宽的 1/6**（写成 1/3 会把删除键推出面板 —— 契约测试与
变异各有一条盯着）。文案「重置为默认」、暗琥珀 `(0.55,0.33,0.05)`（保存=墨黑 / 删除=警示红），
字号 15、5 字 ≈ 75px < 110px 列宽。补丁脚本 `scripts/dev/prefab_patch_prompt_reset.py`：
**文本克隆** SavePromptBtn 的 9 个对象（GO+RT+CanvasRenderer+Image+Button+子GO+子RT+子CanvasRenderer+子Text），
整段替换 fileID（`884…0100`–`108`；`…001–009` 已被 DeletePromptBtn 占用），只覆盖少数几个字段 →
字段集合与 GUID 引用与原件逐字相同。实测 638 → 647 对象，md5 `dfba8be8521b4ce73499731c9d54ec70`，
二次跑字节完全一致（幂等），且**独立 diff 复核**只有预期的 4 处改动（新建键 anchorMax、
PagePrompt 的 m_Children、删除键 anchorMin —— 保存键本来就是 0.5 所以是零改动）。
踩坑记录：① `subn` 的**字符串**替换式会把中文转义 `\uXXXX` 当正则转义 → `bad escape \u`，
必须用 lambda 形式；② `collect_subtree` 里子 RT 被 append 两次会让 id_map 末次赋值覆盖号段
（结果侥幸自洽，但属于"靠巧合正确"）；③ 补丁脚本 import 时包 `sys.stdout` 会让 pytest 捕获流
在收尾时报 `I/O operation on closed file` → 改为只在 `main()` 里包。

**⑥ 两段确认抽成 `TwoStepConfirm`**（删除 / 重置共用，零 Unity 依赖）：
`First`（只武装）/ `Second`（窗口内再击，执行前自动解除）/ `Expired`（过期作废，返回时已解除）。
窗口判据是**严格大于**（恰好 3.0 秒仍算来得及），与内联时代 `Time.time - _deleteArmTime > 3f`
一字不差；`TwoStepConfirmTests` 45 项断言把边界（恰好 3 秒、过期重来、执行后不残留武装、
未武装绝不直接执行、非法窗口回落默认、时钟倒退）钉死。`SelectFile` 换文件时必须
`DisarmReset()`（防"在 A 上武装、在 B 上执行"）。

**⑦ 升级错配**：新 DLL + 旧 exe → Python 抛 `unknown method: reset_prompt`，C# 翻成
「当前 Python 侧不支持重置（AgentLoopServer.exe 未升级），请更新后重试」；
`CollectRefs` 对缺失节点是 null 容忍的（老 AB 上只是按钮不出现），装配日志里点出
`DeletePromptBtn=/ResetPromptBtn=` 存在性（"预制件没打好"与"代码路径接错"在实机上表现一样）。
