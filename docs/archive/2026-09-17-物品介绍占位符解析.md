# 物品/装备介绍的占位符：让它们走同一个解析器

> ⚠ **已归档**。本文是一次性排查记录，没有对应的现状文档，**日常开发不用看**。
>
> **结局**：`ResolveSkillSigils` 从功法说明一条路扩到物品介绍，两个消费者共用同一解析器。

---

**症状**（别人反馈的原版物品，`inspect_unit(classes=["inventory"])`）：
`残·灵盾符×6（单价48，小计288）——吸收使用者当前&608211_kcll&%的灵力…护盾持续&608211_cxsj&秒。`
面板上这句是「当前 **30**% … 持续 **60** 秒」（`ConfBattleSkillValue`：`&608211_kcll` 十列皆 3000、`valueScale=x0.01|f0`；
`&608211_cxsj` 皆 60000、`x0.001|f0`）。同一张图里还有第三方 mod 的气运 `&npc_atk&` —— 那种 key
**在整个游戏目录里都不存在**（全盘 grep 实证），不是我们漏解析，改不了。

**根因**：占位符解析（`ResolveSkillSigils`）只挂在**功法说明**那条路（09-13 那次修的）；
物品/装备介绍（`PropsDetails` / `EquipsDetails`）只做了 `GameTool.LS`，`&…&` 原样进 JSON、进模型、进面板。
不是"忘写"，是**覆盖面**问题 —— 所以这次不是"再写一个解析器"，而是把两路合并到同一个入口。

**① 列语义 = 境界，不是品质**（唯一一处"猜错也看着像正常数字"的地方）

| 依据 | 结论 |
|---|---|
| `BattleSkillValue.xlsx` 表头 | `C..L` = **境界1数值..境界10数值**；`P` = **显示数值缩放**；`M` = 怪物专用数值（悬浮窗用不到） |
| `ItemPill.xlsx` 表头 | `I` = **道具境界**（字段名 `grade`）：残·灵盾符..道·灵盾符 = **1..10** |
| `ItemProps.xlsx` 表头 | `I` = **物品品质**（字段名 `level`，1..6 = 凡品/下品/中品/上品/极品/仙品）——**另一根轴** |
| 反例（必须记住） | 残(境界1)与真(境界2)的**品质都是 2**，但 `&608213_shwl&` 对二者是 **125 / 200**；拿品质当列 = 算成同品阶的数 |
| 10 个品阶共用一条介绍 | 迅雷符 6082020..6082029 的 `desc` 文本**完全相同**、sigil 也相同 —— 唯一能区分的就是列：`&608203_qtsh&` = 80/128/204/…/5454 |
| 运行时拿不到 `grade` | `DataProps.PropsData` 上**没有** `grade`（只有 `propsID`/`propsCount`/`propsItem`/`soleID`/values）；`grade` 在 `PropsArtifact`/`MartialData` 上。运行时境界只能靠 `new BattleSkillValueData(propsData).grade`（下面第三个来源） |

实测影响面：物品 desc 共 **60 个物品 / 141 处 sigil**，其中 **107 处十列全同**（选哪列都对，本次投诉的灵盾符就在其中）、
**34 处与境界相关**（迅雷符/拘灵符/3 个蘑菇/盾铠符 —— 这些才是"猜错就错几十倍"的）。

**② 实现：一个扫描器 + 两个取值回调**

```
PropsSigilCore.Scan(text, valueOf, textOf)      ← 共享：切 &…& / $…$、$ 未命中判定、残留计数（csharp/PropsSigilCore.cs）
   ├─ 技能说明：valueOf = expr => TryResolveValue(expr, vd)   vd = new BattleSkillValueData(md)
   └─ 物品介绍：valueOf = key  => PropsScaledValue(...)       列自己定（见下）
```
* 境界来源优先级：配置表 `ItemPill/ItemSkill/ItemRarityMaterials.grade`（可审计，Excel 表头写明「道具境界」）
  → 运行时 `new BattleSkillValueData(propsData).grade` → 都没有则 0（未知）。
* **绝不猜**：境界未知且十列不一致 → `PickKind.Ambiguous` → 原样保留占位符 + `★介绍占位符境界未知★`（去重封顶 40）。
  只有"十列全同"允许无歧义兜底（取第一列 ≡ 取任何一列）。`"0"` 是**合法值**、空串才是缺失（C# 单测钉死）。
* 介绍流水线：`GameTool.LS(desc)` → 占位符解析 → `StripRichTags`（**565 条**物品 desc 带 `<g>`/`<color=#057600>`/`<size=12>`，
  面板要、模型不要）；解析抛异常 → 退回 LS 原文 + 留痕（绝不整条落空）。
* 真机判据（一次性日志，前 8 件带占位符的道具）：
  `[Props] 介绍占位符 slot=inventory id=6082030 type=1 vdGrade=? confGrade=1 替换=2 残留=0 片段=…`
  —— 列到底选得对不对，只能拿游戏悬浮窗跟这行比（离线看不到方法体）。

**③ 顺带纠正两处早期判断（都靠反射，不靠猜）**

* `ConfBattleSkillValue.GetValue` 在 Cpp2IL 原始签名里是 `private`，**但 Unhollower 代理把它暴露成 public**，
  所以现有技能路径的 `GetValue(key, vd)` 是**有效调用**、不是被 try/catch 吞掉的死代码。
  ⇒ **判断"能不能调"必须看 `MelonLoader\Managed\Assembly-CSharp.dll`（代理），不是 Cpp2IL 产物**。
* `BattleSkillValueData` 有公开构造 `(DataProps.PropsData propsData)` / `(int grade, int level)`，
  这正是"道具自己的取值上下文"入口（不是我们发明的写法）。

**④ 离线反射工具（以后不用开游戏猜 API）**

`python scripts/dev/…` 之外新增 `reference/il2cpp/dump_types.ps1`：反射任意类型的**构造函数/属性/字段/方法全签名**（含可见性）。

```
powershell -File F:\agent_loop\reference\il2cpp\dump_types.ps1 -Filter '^BattleSkillValueData$'
```
两个坑：① Cpp2IL 产物要拷到**纯 ASCII 路径**（`F:\_il2cpp_ref\`，25MB）—— PowerShell 5.1 按 GBK 读脚本，
默认的中文游戏路径会变成乱码；② 反射**原始签名**用 Cpp2IL 产物、判断**可调用性**用代理，两者结论可能相反（上面 ③）。

**已知取舍 / 待真机确认**：① 3 个蘑菇（`ItemPill.grade = 0`）与盾铠符（无 ItemPill 行）**列定不下来**，
会原样保留占位符 + ★留痕（宁可留着，也不给一个"看着正常"的错数字）；② 含 `|` 的算式在物品 desc 里
实测 **0 处**，那条分支是兜底（走 `EvalMath`，需道具自己的 vd）；③ `vdGrade` 与 `confGrade` 打架时取
配置表并留 `!` 对照，真机一比即可定论；④ 顺带把 565 条 desc 的富文本洗掉了 —— 面板观感随之变化
（`●` 那行不再变小），这是"模型可读"与"面板好看"二选一，选了前者（与技能说明同口径）。
