# 工具结果默认折成一行摘要 + 回合收口整组收起

> ⚠ **已归档**。现状见 [`docs/features/tool-result-contract.md`](../features/tool-result-contract.md)。本文只保留当时的排查过程与被推翻的中间结论，**追溯「这个结论怎么来的」时才需要读**。
>
> **结局**：默认折叠 + 点击展开已落地，摘要形态沿用至今。

---

**症状（用户截图）**：行动记录里工具返回**全文直出** —— 一屏 28 行全是道具词条
（`unit id: FmTzJ5` + 剑法/丹药/装备/宗门推荐信/石沉戒…占满整屏高度）。用户："这种形式我不喜欢，
改为可展开形式，默认是折叠，点击之后可展开"。

**量化**（扫两个世界全部账本）：21 条工具结果，中位 267 字、p90 789 字、最长 908 字/17 行；
**工具原文合计 6901 字 > 同期 NPC 台词旁白合计 6237 字** —— 那一屏里一半以上的可读内容是工具原文。

**根因（三条，都不是"某处写错一个变量"）**：
1. **代码与自家文档不符**：`README.md` / `docs/WORKSHOP_PAGE_BBCODE.txt` 都写着「执行的时候自动展开，
   **做完自动收起**，想细看随时点开」，`docs/release/SHOTS.md` 的拍摄手册也叫人「等他回完之后，**手动把
   「行动记录」点开**再截图」——都假定收口后是收起的。但 `StepGroup.Finish()` 里
   `if (!_autoOpen && _body != null)` 把行动记录（`autoOpen: true`）**明确排除**在收起之外，
   注释还写着"完成后保持展开"。**行为是故意的，但与对外说明相反**。
2. **结果行没有折叠层**：`AddResultLine` 把 `prefix + text` 一次性喂给 `Text`，全文直出、无点击切换。
3. **展开会顶飞阅读位置**：`LateUpdate` 的流式跟随把"内容长高"当成"新内容到达" → `verticalNormalizedPosition = 0f`
   钉底 ⇒ 用户点开一行，看到的是这段文字的**结尾**（开头被顶出视口上沿）。

**修法（三层，一条不变量贯穿：只折视图，不改数据）**：
| 层 | 改动 | 位置 |
|---|---|---|
| L1 组级 | 收口（他动完手、开始说话）整组收起；**手动点开过的组不收**（手动优先）；标题箭头在收起**之后**刷新 | `ChatItemViews.StepGroup.Finish()` |
| L2 行级 | 结果行默认折成 `▸ ✓ 摘要…（共 N 字，点击展开）`，点击展开 `▾ ✓ ` + **原文**；短结果（单行 ≤ 40 字）不折；**错误行默认展开** | `ChatItemViews.AddResultLine` + 新 `UI/ToolFoldPolicy.cs` |
| 位置 | 点开后**不跳**：关掉跟随（语义=用户接管屏幕，同滚轮上滚）+ 等布局生效后滚"刚好够"的像素（装得下就一动不动；行比视口高就把行顶对齐视口顶） | `ChatWindow.OnFoldToggled / TickFoldAnchor` |

* **判定抽成零 Unity 依赖的 `UI/ToolFoldPolicy.cs`**（`ShouldFold` / `CollapsedLine` / `ExpandedLine` /
  `ExpandByDefault` / `RevealDelta`），与 `BubbleCommitPolicy` 同款——纯逻辑才能被 net8.0 单测跑判定表。
* **展开态一字不改**是硬约束：摘要是"预告"不是替代品，`Substring` 只允许出现在 `CollapsedLine` 里。
* **摘要必须先剥富文本标签**（`<color=#004FCA>` 这类结果里很多）：按字数硬截会把标签截一半 →
  屏幕上出现 `<colo` 或整段串色。字数报的是**可读字符数**（剥标签+压空白后）。
* **`LateUpdate` 里校正排在钉底之前并吃掉这一帧**；`_foldAnchorWait < 3` 保证布局万一不生效也不会
  把状态挂死（挂死 = LateUpdate 永远早退）。
* 位置校正只写 `Content.anchoredPosition`（绝对偏移，UGUI 真正存着的量），**不写** `verticalNormalizedPosition`
  （派生值 = 偏移 ÷ 可滚范围；内容长高后按比例写会整体漂）。实测：贴底时长高，Unity 自己**不会**动视图
  （内容向下长，覆盖范围只增不减），顶飞阅读位置的只有我们那句"变高就钉底"。
* **批量重建后要"钉底保持"（09-17 补）**：`ChatWindow.HoldScrollAtBottom()`（`ResetContent` 与
  `DrainSoloFrames` 各调一次）让接下来 6 帧**无条件**钉底，并在这几帧里跳过"位置不在底部 ⇒
  停跟随"那条判决。为什么必须补：一次画几十行（历史重放 / 未闭合回合整段重演）时布局要好几帧
  才结算，钉底那一刻量到的 Content 高度可能还是中间态；随后布局定稿会让位置**不再在底部**，
  而下一帧是"内容没长高" ⇒ `else if (!AtBottom()) _followingBottom = false;` 把跟随**永久关掉**，
  视图停在顶部（实机：重开窗后要自己往下翻）。保持期把这段结算窗口整个盖住；
  保持结束后第一帧因两个判据归零而必判"长了"，再钉一次。
* **失败/慢速回合的兼容**：`FinishStepProcess()` 一回合被调多次（正文整段 `ChatPresenter.cs:866`、
  首个 delta `:908`、收口 `:940`），所以"收口"的准确语义是**他一开始说话就收起**，不是回合彻底结束。

**已知取舍（改之前先读）**：
* 点开折叠行会**暂停自动跟随**（用户接管屏幕，同滚轮上滚），滚回底部自动恢复（`AtBottom()` 自愈）。
  这是有意的：不暂停的话，下一批流式正文一到就把他正在读的这段顶走。用户 09-16 选定该方案（B 档）。
* 折叠状态存在行对象上：重开窗/换 NPC/删除后重放 = 行被销毁重建 ⇒ 回到默认折叠。符合"默认折叠"语义；
  要跨重开保留得按 turn/step/call_id 存状态表（成本不划算，不做）。
* 内容变短（收起）导致的滚动越界，Unity 会把偏移夹回范围内 —— 那一下**补不回来**，只能"能保就保"。
* 调用行（参数原文）**保持不折**：账本里实测中位 42 字、最长 74 字，基本一行；`world_ai_action` 传台词
  那类若将来变长，可复用同一套（`AddCall` 走 `AddTextLine`）。
