# 多件赠送：原生一次只处理一件

> ⚠ **已归档**。本文是一次性排查记录，没有对应的现状文档，**日常开发不用看**。
>
> **结局**：定案：一件走原生、多件走自制窗 + 直写。

---

**症状**（用户实测）：一次让 NPC 送 4 件道具，**只有第一件生效**，原生窗里也只显示一件，
选「我收下了」也只到手一件 —— 但**工具结果写着"全部收下"**。

**证据链（四条，指向同一个结论）**

| 证据 | 内容 |
|---|---|
| 引擎自证计数（真机两次） | `[Give] 预检 拆出道具数=4 giveProps=4` → `[UnitAction] give_item receiveProps=1 refuseProps=0`；隔一轮 3 件同样 `receiveProps=1` |
| 签名（interop） | `UnitActionRoleGive`：`ctor(WorldUnitBase, List<PropsData>)` + `giveProps/receiveProps/refuseProps`(List) + **`propsData`（单数）**；私有 `OnEnd()` 里两个闭包 `__OnEnd_b__11_0/1(Int32)` 都在找"这一件"；另有 `FeedbackAllProps()` 负责把没送出去的**退回发起方** |
| 配表文案（LocalText/RoleLogLocal 105675） | 剧情 21701：「我这里有一个{0}准备赠于你，你需要此物吗？」+ 选项 217012「我收下了」／217011「我不需要这个」——**通篇单数** |
| 我们自己的预检 | `IsCreate` 两次都抛 `NullReferenceException`（`propsData` 在建动作前是 null，正是它在 `IsCreate` 里被访问） |

⇒ 列表只是账本，真正走流程的是 `propsData`。**多件不是"暂时不支持"，是这套 API 的设计口径。**

**顺带挖出的第二个 bug（报告失真）**：`items` 是**我们拆栈时的愿望单**（每件都写了 `actual`），
而引擎真值在 `accepted_count`（= `receiveProps.Count`）。旧渲染只在 `refused_count > 0` 时才提
"部分收下"，否则一律写"收下了赠礼（全列）" ⇒ **1 件被写成 4 件**，模型于是在游戏里宣布"都给你了"。

**修法（用户拍板 A：自制确认窗 + 直写 + 复刻原生副作用）**

* **1 件仍走原生**（`UnitActionRoleGive` + `UnitActionPending` 挂起）：原生立绘/文案/副作用都精确，不动它。
* **≥2 件走自制窗**（`ModIds.DramaEconomyItemBase`，与纯灵石窗同段）：正文列全清单
  （"姜萌愿赠你：六品化瘀丹×10、六品蓄力丹×3（当面赠达），是否一并收下？"），选项照抄原生
  「我收下了／我不需要这个」；点一次 → 逐件 `AddProps` **全部到账**（`delivered_all:true`）。
* **副作用自己补**（原生的那两件）：① 好感 `AddIntim(giverId, GiftIntimPerItem)` —— 值取配表
  `RoleGive.closeParaA = 15`，**只加"收礼方对送礼方"**（收礼的语义）；② 角色日志照抄原生 key
  `eventLogRoleGive21311`（送礼方视角）/`21312`（收礼方视角），参数 `{itemLink<propsID>}`，
  `{name|A}/{name|B}` 由 `UnitConditionData(送礼方,收礼方)` 提供。
* **绝不吞道具**：这批道具是 `TakePropsFromBag` 拆出来的 ⇒ 窗没开起来 / 收礼方背包不可用 /
  入包异常，三条路都 `RollbackGive` 原样放回。
* **不许猜好感**：原生 `OnEnd` 的公式在 native 体内看不到 ⇒ **两条路都留探针**
  （`[Give] 好感探针 原生赠礼/多件直写 收礼方对送礼方 X→Y`），真机送一次即可核对该常量；
  探针里还带一条自检（`Δ != 15` 时打印"★ AddIntim 的 value 可能是绝对值语义"）。
* **渲染层按引擎真值说话**：`accepted_count < 件数` 时逐字点名"收下的那件 / 未送达的那几件
  （引擎一次只处理一件，其余已退回发起方）"；缺 `accepted_count` 的旧载荷保持旧文案不回归。

**验收**：`tests/test_give_multi_contract.py`（10 项：C# 接线 7 + 渲染行为 3）、
`scripts/dev/mutate_check_give_multi.py` **变异 18 项全部捕获**。第一次跑漏了 **4 项**，
全是"断言太弱"：多件分支里 `ShowDramaService.ShowConfirm` 被换成死代码仍算通过（改成钉
`JObject opened = Claimed(...)` 整句）、探针计数把**注释**也算进去了（改成只数 `ModMain.P("[Give] 好感探针`）、
以及"收到的/没送到的"只查名字出现过（got/miss 切反、按愿望单全列两种错法都能蒙过 ⇒ 改成逐字钉
`收下了赠礼（六品化瘀丹×10）` 与 `未送达：六品蓄力丹×3、…`）。全量 pytest 见下节。
