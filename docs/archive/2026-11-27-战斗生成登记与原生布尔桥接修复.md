# 战斗生成登记与原生布尔桥接修复

## 问题与定案证据

秦雨华所在副本 2803、触发器 41040 入场后，玩家仍能移动、普攻，但其他单位停止行动。全局计时器继续前进，战斗计时器停住。异常链为零 ID 入场台词进入 `UnitDialogue`，随后 `HretHandler` 空引用。

本机原生调用给 `BattleFunction.AddBattleUnit` 的第十参数写入单字节 false；本地队友识别挂钩启用后的实际 Mono 桥接以四字节比较读取该参数，将非零栈填充误认成 true。游戏因此把 `dialogueDrama=false` 读成 true，对 `endDramaID=0` 执行冒字流程。仅在参数上加 `MarshalAs(I1)` 的隔离实验未能解决本机桥接问题。

单变量 A/B 已完成：A 轮 PID20060 有该挂钩并复现；B 轮 PID21908 只取消该类的 Harmony 自动发现标记，加载模组目录列表一致，两个静态生成入口恢复原生指令。用户确认同场打完且战后剧情正常，日志记录 `BattleEnd(true)` 和后续剧情正常结束。此前新增的本地识别挂钩是这次故障的触发点；不据此认定其他版本或无关模组存在同一缺陷。

本机完整证据目录：`D:/Code/ggbh/work/qin-repro-20261127-011620`，B 轮结论在 `B-acceptance-20261127-014421/验收结论.md`。用于 A/B 的 DLL 只关闭登记，不能作为功能完整的最终修复。

## 正式实现

1. `TeamBattleSpawnIdentity` 精确挂钩 `UnitCtrlHumanNPC.InitData(WorldUnitData, UnitType)` 的后置回调。此入口无布尔参数，返回 void，不改入场参数、台词内容或原生剧情流程。
2. 带本模组标识的数组生成命令建立识别范围，记录本场数据、实际槽、世界数据指针和角色 ID。NPC 初始化回调只观察完全匹配的控制器；同名、相同 ID 的另一份世界数据以及其他命令都不能借用该范围。
3. 初始化成功仅保存候选。生成命令 Finalizer 在无异常时提交候选，恢复 `RegisterBattleUnit` 的死亡和战后登记。初始化后命令抛错、空生成均不提交；Finalizer 在所有路径恢复有效外层范围。
4. 嵌套非本模组命令暂时隔离外层范围，嵌套本模组命令独立登记。登记核心有生命周期代数，清理或重读后即使原生指针被复用，旧范围也不能再提交。
5. 保留实际槽映射、原生命令队列、决斗同意、真实参战后才置 `alTeamIn`、真实伤者重伤及战后归队限制。

本机 API 元数据确认 `InitData` 签名，RVA 为 `0x2CB5550`。原生生成入口经 `CreateUnitHuman` 同步调用控制器初始化；选择初始化完成位置，避免把仅已分配但尚未初始化的单位认作队友。RVA 仅用于本机构建证据，不写进运行时代码。
