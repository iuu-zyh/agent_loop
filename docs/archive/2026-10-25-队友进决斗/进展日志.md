## 2026-10-26 · 第三轮（核实"战斗内剧情 → 队友经历"，补护栏）

### 结论：这条链路**上一轮已经实现**，这一轮做的是核实与钉死

用户问「战斗里的剧情 UI 与选项，打完有没有写进队友的经历（玩家自己不用写）」。
核实结果：**有**，走的是账本战斗窗那条既有链路，决斗与副本共用同一段取数逻辑：

```
同意参战 → MID&004 触发器 → addBattleNPCData → TeamContainerInject.InjectInto
           → DramaLedger.BeginWindow("")                 ← 窗起点（两条路共用）
战斗中 每页/每选项 → DramaLedger.NotePage / NoteOption   ← 全量、无 TTL、判不出归属也记
BattleExit → DramaLedger.EndWindow("")                   ← 第一件事，早于任何 return
           → WriteDuelLogs(player) → WriteDungeonDrama(logMgr, player, duel:true)
           → TryAddLog(logMgr, mate, 决斗见闻模板, {同行者名单, 成品句})
```

三条口径（都有契约测试钉住）：

| 口径 | 实现点 |
|---|---|
| **只写队友，玩家的经历不写** | `WriteDungeonDrama` 的循环只遍历 `_mates`，没有一条 `TryAddLog(..., player, ...)` |
| **过滤我方确认窗与事件钉子** | 确认窗段号 `Mod+200` 落在账本私有区间（`Mod..Mod+999`）⇒ 队友不会记得"你问他要不要参战" |
| **有上限且不静默** | 16 行 / 单行 70 字 / 整段 1000 字；丢了多少条写进日志（`DroppedCount`） |

### 这一轮补的东西

| 项 | 内容 |
|---|---|
| `tests/test_team_duel_join_contract.py` | **10 → 15 项**：①剧情只写队友 ②决斗见闻必须用决斗那两行模板 ③过滤事件/私有窗（含"确认窗段号必须留在私有区间"）④关窗早于任何 return ⑤格式化上限与截断日志 |
| `docs/archive/2026-10-25-队友进决斗/事实链.md` | 新增 **F8**：用真机时间戳逐拍核对"战斗窗到底罩住了什么"（含 4 条结论 + 1 条待验证 U5） |

### 边界（一句话版）

窗 = **[队友进场 … `BattleExit`]**，所以：

- ✅ 战斗中演的页与选项；
- ✅ 战后处置页（`20403/20404`）+ **玩家选的处置**（真机 18:57:57 的证据：比 `BattleEnd` 还早）；
- ❌ 开战前的**前情**（寻仇开场页 `20203` 比应战窗早 20 秒；副本进入页 `610911` 早 95 秒）。

⇒ 队友记得"这一仗怎么打的"，不记得"为什么要打"。要改属 02 §11 的 P3/P4：
必须把窗起点前移到"有人对你动手"这个**事实**上（攻击动作创建 / 开战页出现），
不许用"往前 N 秒"。

### 抓到的 bug：**换世界判据用托管包装引用** ⇒ `_asked` 被每 0.25s 清一次 ⇒ 窗一直弹

- 日志形态：`换世界 ⇒ 表态与对手已清空` **3555 行**，`进入战前 ⇒ 本场可问` 199 行，4 次弹窗 4 次回答；
  最后 `answer=None`（答案被下一次 Reset 抹掉），一直没进 `IntoBattle`（所以 `[TeamInject]`/`触发器自检` 一行都没有）。
- 根因：IL2CPP 每次取 `g.world` 可能给出**新的托管包装**（同一 native 对象）⇒ `ReferenceEquals` 恒 false。
  本仓 `UnitSnapshot.cs:44` / `RelationNetwork.cs:321` 早就记过这个坑，这次在"世界身份"上又踩了一次。
- 修法：比**原生物件指针** `w.Pointer`；`hadWorld` 区分"首次进世界"。契约测试
  `test_world_change_uses_native_pointer` 钉住"不许改回 ReferenceEquals"。

### 顺带确认的一件事
