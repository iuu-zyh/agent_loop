> ⚠ **本目录已归档（2026-10-29）**。功能已实现完毕，**现状请看 [`docs/features/team-duel-join.md`](../../features/team-duel-join.md)**。

>
> 本目录只服务一件事：**让"被攻击 / 寻仇"这类战斗也能带队友上场，并且战后写对经历**。
> 目录里只放这一件事的调研事实、方案与进展；不重复 `docs/features/team.md`（组队机制总览）、
> `docs/reference/dungeon-type-mapping.md`（副本类型与触发器作用域）。

## 一句话结论（先看这个）

**攻击 / 寻仇开出来的战斗，本身就是一个 `type=40` 的普通副本（`dungeonID=11`）；队友进不去，
不是"引擎不支持"，而是我们在 `DungeonTrigger` 里写的 `dungeonType` 白名单把 40 排除掉了。**
所以这件事不需要造新机制：把 40 纳入 → 在 `addBattleNPCData` 这一口加"玩家同意"闸 →
战后按 `dungeonBaseItem.type` 分支写另一套经历文案。

### 一次探针看全（10-26 复核后）

只跑**一场**：队伍里至少 1 人 → 让一个有仇的 NPC 攻击你 → 应战窗上点「一起应战」→ 打完在处置页选一个处置。

整个过程应当依次出现这些行（按出现顺序）。**每行都对应一个待确认项**：

| 日志 | 回答什么 | 不看也行？ |
|---|---|---|
| `窗模板：运行时注册成功 id=-803158251` + `选项行：✅ 注册成功 …` | 没导出时窗口仍可用（第一次决斗各打一次） | 导出后就变成 `窗模板：用表里的 …` |
| `[TeamJoin] 弹出确认窗：对手=X 队=N 窗模板=2 层顶=MapBattlePre` | 问答确实发生在应战窗上 | 否 |
| `[TeamJoin] 确认窗已显示（层顶=UICustomDramaDyn，模板=2）` | **U3**：窗在应战窗之上（若打出 `⚠ 确认窗没显示出来` ⇒ 层级不对，本功能会退化成"不带队友"） | 否 |
| `[TeamJoin] 玩家选择：一起应战（对手=X）` | 回调通了（选项行注册是否必要，看这一行是否出现） | 否 |
| （可能出现）`[TeamJoin] 对手取自攻击链目标 uid=…（页面上判不出）` | 工具发起的攻击：开场页判不出对方，用我方攻击链兜底 | 只在页面判不出时出现 |

| `[TeamJoin] 触发器自检：决斗 id=11 候选 N 条 […-803158447] 其中带 addBattleNPCData 的 M 条` + `触发器自检 ⇒ ✅ … IsTrigger=TRUE（引擎判定它会执行）` | **导出与注入链**：`IsTrigger=FALSE` 或"不在候选里"= 还没导出 | 否 |

再来一场**普通副本**对照（证明没回归）：`★直塞完成★` 照旧，经历文案回到
`与「…」同闯秘境，斩杀…`（不是"并肩应战"）。

> 只剩一件**必须人眼**的事：窗是不是真的画在应战窗上面（日志只能证明"它被创建且可见"）。
> 若画面被应战窗盖住，`确认窗已显示` 这一行会和实际相反 —— 所以**看画面 + 对日志**一次做完。

## 三个必须先分清的概念（后面所有讨论都建立在这上面）

| 概念 | 是什么 | 由谁产生 |
|---|---|---|
| **决策组件** | 玩家身上挂一枚「结伴而行」气运，代表"这个 NPC 是我的队友" | `team` 工具（`TeamTool`），最多 3 人 |
| **容器直塞** | 战斗初始化时把队友写进 `battle.data.npcUnits`，让引擎的 `addBattleUnit_3/4/5` 按位取人 | `TeamContainerInject` 钩 `BattleFunction.AddBattleNPCData` |
| **战后收尾** | 归队传送 / 重伤离队 / 击杀战报 / 写经历 / 写剧情 | `TeamBattleFollowup` 钩 `BattleEndFront` + `BattleExit` |

**"组队只对副本生效"这句不准确**：组队对所有**会走 `DungeonTrigger` 的战斗**生效。
决斗（type 40）也会走 `DungeonTrigger`——只是被白名单挡在门外，连钩子都没被调到。
