## §1 两条路线对比

| 维度 | 路线 A（玩家参战） | 路线 B（引擎观战） |
|---|---|---|
| 用户目标"NPC 打 NPC" | **部分**：A/B 同场但玩家也是当事人 | **完全**：A/B 单挑，玩家旁观 |
| 谁开打 | 玩家（代 A 出手）或目标打玩家 | A 对 B，与玩家无关 |
| 战斗载体 | `dungeonID=11`（`type=40` 决斗） | `dungeonID=4001`（`type=79`，`sceneBaseID=14`） |
| 配表改动 | **必须**新增 `DungeonTrigger MID&004`（否则队友进不来） | **不需要** |
| 代码改动面 | `ToolExecutor.attack` + schema + 文案（3 处） | 新增 `NpcDuel` + `BattleOutcome` 分支 + schema + 文案（4 处） |
| 引擎证据强度 | **高**（这条链本仓已在跑，真机日志齐全） | **中高**（反编 + 第三方 mod 实证；缺本仓真机） |
| 失败时的表现 | 队友没进来 → 玩家 1v1（能打，只是没实现意图） | 观战不开 → 必须显式降级到纯结算（不能空等） |
| 可扩展性 | 低（永远 2 方 + 玩家） | **高**（任意两 NPC；将来可做 NPC 阵营战/擂台） |
| 与"观战/督战"大比玩法 | 无关 | 同源（都是 `npcFightUnits`） |

## §2 推荐执行顺序

### P0 · 先做 B3「后台结算」（1 天）

**为什么先做它**：它不依赖任何未验证行为（`UnitBattle` 是纯算术，第三方 mod 已在用），
却立刻让"NPC 能打 NPC"这件事**成立**：模型调 `attack(target=B)` → 引擎算出胜负 → 我们自己写经历/好感 →
结果回给模型。没有场景、没有新配表、没有新挂点。

产出：`world_ai_action(attack, target=NPC)` 可用；`watch` 缺省 `no`（此时先不弹观战）。

### P1 · 探针（半天，一次真机）

跑 [§3](#3-探针清单u1u5) 的 U1–U5。**探针只读、不改行为**，用诊断开关文件触发（同
`_diag_initiative_force.txt` 范式，一次即停）。

### P2 · 若 U1/U2 通过 → 接 B1「真观战」（1–2 天）

`watch=ask` 时先问一句（复用 `ShowDramaService.ShowConfirmSimple`，
**不占 `DramaGate` 槽位**，范式见 [队友进决斗/事实链.md F6](../2026-10-25-队友进决斗/事实链.md)）；
同意 → `NpcDuel.TryWatch`；拒绝 → B3。

### P3 · 若产品要"玩家也上" → 接 A2（1 天 + 一行配表）

`watch=no` 且玩家与 A 同队时，改成玩家代打（`player.CreateAction(new UnitActionRoleAttack(B), true)`），
前置是 `DungeonTrigger MID&004`（见 [02 §4.1](路线A-玩家参战.md)）。

> 顺序理由：**先让能力成立（B3），再让它好看（B1），最后才是"玩家也要打"（A2）**。
> 反过来做（先配表、先玩家参战）会把"两个 NPC 能不能打"这个核心问题埋进 UI 与配表噪声里。

## §3 探针清单（U1–U5）

> **10-26 更新：本节的 U1 / U4 / U6 已经不需要探针了** —— U1 用反编读穿（分派是纯字符串比较，
> 与"在不在剧情里"无关，且第三方 mod 就是在按钮回调里这么调的）；U4 撤销（引擎与剧情都不要求同格，
> 观战副本在战场内重新摆位，见 [01 §F9](../../reference/engine-facts.md)）；U6 撤销（`isRealBattle` 不控场景）。
> 剩下 U2 / U3 / U7 已合并进**一次** `_diag_npc_duel.txt` 触发，
> 报告与判读表见 [03 §8.6](路线B-引擎观战.md)。下面的表格保留作历史。

> 与仓里既有规矩一致：**探针阶段只编译 + 部署 + 上机取数**，不写契约、不做变异验证；
> 判据未经真机证实前**不写护栏**。

新增一个诊断开关 `F:\agent_loop\_diag_npc_duel.txt`（`DiagSwitches` 同范式，每 2s 重读、一次即停）：

```ini
# 形如：
left=江宇文
right=姜萌
watch=1          # 1 = 走 dramaUnitBattle 观战；0 = 只走 UnitBattle 结算
```

| # | 探针读什么 | 判据（通过长什么样） |
|---|---|---|
| U1 | `OptionsFunction("dramaUnitBattle_1_2", …)` 后日志有无 `进入副本：4001` / `SceneBattle.Init` | 有 ⇒ 非剧情上下文可用 |
| U2 | 观战场景里 `g.world.battle.data` 的 `npcFightUnits` 两人、玩家单位是否在场上、`UIMapBattlePre` 是否弹过 | 打印一次全量现场（`BattleStart` 时） |
| U3 | `BattleEndFront` 时：两人各自的 `isDie` / HP；`BattleEndMgr.BattleEnd(isWin)` 的实参；最后一页剧情有没有 | 能唯一确定胜者 ⇒ 结果可回填 |
| U4 | 发起前 `IsSameGrid` / `residueDay`；不同格与低精力各跑一次 | 记录引擎拒绝码与文案（`NativeRefuseWhy` 同源） |
| U5 | `UnitBattle(a,b)` 前后：两人经历日志条数、好感值、伤势 | 差值 ≠ 0 ⇒ 引擎副作用，别双写 |
| U6 | （路线 A2）`player.CreateAction(new UnitActionRoleAttack(B))` 是否照常弹 `UIMapBattlePre`、战后处置页是否同形 | 弹且同形 ⇒ A2 可用 |

**探针一律走 `ModMain.P` 打一行 `[NpcDuelProbe]` 前缀**，便于 `grep`。

## §4 决策建议（一句话）

- 只要"NPC 之间能打" → **B3**（今天就能做）
- 要"玩家在边上看" → **B1**（探针通过后做）
- 要"玩家也参战、带队友" → **A2**（配表 + 一行代码）
- 想做"宗门大比那种赛事" → 另立项目，复用 `MatchFight` / `UIMatchFight`，**不要**塞进 `attack`

## §5 与既有设计的关系（避免重复造）

| 已有资产 | 本任务怎么用 |
|---|---|
| `DramaGate` + `pending` 心跳 | 观战/结算都要挂起，直接复用（Python 侧 deadline 顺延已有） |
| `BattleOutcome` | 现用于 spar/attack（玩家侧）；本任务**新增** `npc_watch` 台账，不污染原分支 |
| `BattleEndHook` / `BattleEndFront` | 收口的唯一证据源 |
| `TeamContainerInject` | 路线 A 的队友入场，逻辑不改 |
| `ShowConfirmSimple` | "要不要观战"的询问窗，不占槽位 |
| `text_render` | 三种形态的文案集中在这里，C# 只给事实 |
