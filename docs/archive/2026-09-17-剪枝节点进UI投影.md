# 工具结果剪枝的替换节点会进 UI 投影

> ⚠ **已归档**。现状见 [`docs/features/tool-result-contract.md`](../features/tool-result-contract.md)。本文只保留当时的排查过程与被推翻的中间结论，**追溯「这个结论怎么来的」时才需要读**。
>
> **结局**：复核顺带抓到，已修：UI 投影开始认 `surfaceOp`。

---

**怎么发现的**：复核 D.16 那一轮顺带验"pruner 的用量到底有没有记账"时，把「超预算工具结果 → 剪枝 →
开窗回放」这条链在真 `Session` 上跑了一遍 —— 顺手打印投影出来的 UI 时间线，看到**两条** `tool_result`。

**根因**：`ToolResultPruner` 折完一个超预算结果，会 `session.append("tool/result", 折后的消息,
{"surfaceOp": {"op":"replace", …}})` —— 也就是**又写了一条同 `callId` 的 tool/result**（原文留在账本里）。
而 `history.project_ui_history` 只滤两样：`history/delete` 的 seq 与 `source.kind=plugin` 的消息；
它**不看 surfaceOp** ⇒ 原文与摘要各投影一条，玩家每次开窗回放都在「行动记录」里多看到一行
（实测：9000 字原文 + 45 字摘要）。

**为什么必须留原文、滤替换节点**（不是"哪条更好看"）：屏幕上当时显示的是**原文**（结果帧走流式那条路），
而"直播与重放必须逐字一致"是本项目反复钉过的硬规约（§D.8）；压缩折出来的那条是 `plugin` 消息，
本来就滤 —— 同一个语义。删除逻辑不受影响：它走 surface 目录（`history_ops`），不看这个投影。

**修法**：`project_ui_history` 的投影循环里跳过替换节点（3 行 + 注释），
`history.py` 模块 docstring 同步补一句"隐藏的还有一类：替换节点"。

**验收**：`tests/test_ui_history.py::test_project_ui_history_skips_replace_nodes`
（真 `Session` + 真 pruner + 假 LLM：断言投影只出 1 条 `tool_result` 且文本 == 原文，同时断言模型侧仍拿到摘要
—— 剪枝的意义不变）。**逐文件回退验证**：删掉那 3 行 → 该测试如实变红（`len == 2`）→ 按字节还原（md5 校验通过）。
全量 pytest **897 → 898 passed**；`AgentLoopServer.exe` 重打（`--selftest` exit 0，md5 `98059188…`，
旧 exe 存 `backup/deploy_20260917_160741/`）。

> 已知量级：生产上这条**尚未真正触发过** —— 扫过两个世界的账本，最长工具结果 908 字，而剪枝门槛 8192 字
> （见 2026-09-16-工具结果折叠.md 的量化）。属于"门槛一旦被越过就会看到重复"的潜伏 bug。
