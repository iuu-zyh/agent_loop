# 群聊底部统计行的口径：只报「本群期间」的花费

> ⚠ **已归档**。现状见 [`docs/features/group-chat.md`](../features/group-chat.md)。本文只保留当时的排查过程与被推翻的中间结论，**追溯「这个结论怎么来的」时才需要读**。
>
> **结局**：按用户口径落地：只算本群期间，并显式标注。

---

**用户原话**：
> 下面的数据什么时候才会传回来，是回合结束之后就会传回来吗…如果是针对多聊的话会怎么样，
> 针对多聊的话就不能显示各自的上下文和占用率了，但是可以显示总的token数，总输出token、
> 缓存率等（**只计算群聊期间，需要指明**）。

配的截图是**群窗底部一个孤零零的 `None`** —— 那正是预制体 `BG/StatsBar/Text` 的默认文本，
说明这一行在群窗里**从来没被刷过**。

**四个层次的原因（都在这一轮修掉）**

| # | 层 | 病因 | 修法 |
|---|---|---|---|
| ① | 路由 | 群聊的 `stats_update` 漏了 `_extra` ⇒ **没有 room_id**，而群窗唯一准入判据是 `AcceptsRoomFrame`（room_id 相等）⇒ 整帧被丢 | `send_event("stats_update", npc_id=…, **_extra, **snap)`；单聊 `_extra` 为空 ⇒ 逐字节不变 |
| ② | 基线 | `open_room` 回执**不带**任何统计 ⇒ 开窗那一刻无基线，要等第一个成员说完才有第一帧 | 回执补 `roomUsage`（空群给零值），C# `ApplyOpenRoom` 顺手刷新那一行 |
| ③ | 渲染 | 旧写法把 `contextWindow`（**总**上下文，配置事实）也塞进 `if (pressureTokens > 0)` ⇒ 没实测时**连总量一起消失**（用户上一轮问的"没有当前上下文和总上下文"） | 总量与当前值分开判；当前值 `实测 → ≈估算 → —` |
| ④ | 口径 | 群窗拿到的若是**某个成员**的累计 `tokenUsage`，报的是"我在这个 NPC 身上花的"（含单聊）——与"本群花了多少"不是一回事 | 新增**本群口径** `roomUsage`（见下） |

**本群口径怎么算（"只计算群聊期间"）**

* 成员 agent 同时服务单聊与群聊，`UsageTracker` 一 agent 一份账 ⇒ 只有**差**才是群内的量。
  取差点在 `ChatHub._run_turn`：进回合前取 `usage_buckets()`，`finally` 里再取一次，
  差值并在 `Room.group_usage`。
  ★ 必须排在**发 `stats_update` 之前** ★ —— 第一版把取差写在 `RoomFlow._one_speaker` 里
  （`_run_turn` 返回之后），实测那一帧报的是**上一位的账**（自己的量要等下一个成员才出现）。
* 取差必须在**该 agent 的锁内**（群内回合在 `_one_speaker` 里持锁）—— 锁外并发进来的单聊
  回合会把增量算到群里。失败/弃权的回合照算照记（那趟可能已经花了钱）。
* `Room.group_usage` **落盘**（`to_meta`/`from_meta`，老存档缺键 → 空表 → 从 0 涨）。
  只增不减：删消息/压缩**不退钱**（花费是既成事实），这点与 `deleted_seqs` 刻意不同。
* 形状由 `stats.shape_group_usage` 统一整形（与 `tokenUsage` 同形 + `turns`/`steps`/
  `sinceCreated`）：`inputTokens`（= 缓存读+写+未缓存）、`outputTokens`、`totalTokens`、
  `cacheHitPercent`。**不含任何上下文/窗口字段**。

**那一行长什么样**（C# `BuildRoomStatsLine`）

```
本群期间 ｜ 总 1.2M ｜ 输入 1.1M（缓存 900k / 未缓存 200k）｜ 输出 60k ｜ 缓存率 79% ｜ 本群 12轮/30步 ｜ 不含各自单聊
空群：本群期间 ｜ 还没有发言 ｜ 只统计群内消耗（不含各成员的单聊）
```
* 群里**不报上下文/占用率**（每人一份账本，没有可加语义）；`roomUsage` 缺席时（老后端）
  C# 退回成员口径并给那一行加人名前缀（"姜萌 ｜ …"），本群口径自带"本群期间"，**不加人名**。
* "本群 N 轮/M 步" = 群内跑过的**成员回合数**/步数（含弃权与失败）。
