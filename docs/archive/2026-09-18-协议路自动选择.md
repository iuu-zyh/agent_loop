# 三条协议路：为什么 AI 会「换个模型名就全哑」，以及让它自己找路

> ⚠ **已归档**。本文是一次性排查记录，没有对应的现状文档，**日常开发不用看**。
>
> **结局**：改成让客户端自己探路，不再写死单一协议形态。

---

**现象**：用户截图 —— 配置面板底部一行
`server 500: Internal server error ｜ 对方网关 5xx，是它那边的问题，过会儿再试`。
`Player.log` 里对应四行（20:32:29 / 20:32:37 / 20:33:10 / 20:35:26）：

```
[ConfigPresenter] test_llm 失败 kind=server status=500 code=
  model=union-alpha headers=[User-Agent,x-opencode-session]
  message=Internal server error hint=对方网关 5xx，是它那边的问题，过会儿再试
```

也就是说：**这是「测试连接」按钮**（不是对话链路），发起者是我们，500 来自远端。

#### 三层"我以为是 A，其实是 B"

| # | 以为是 | 实际是 | 证据 |
|---|---|---|---|
| ① | 本地 python 服务/游戏桥出错 | **远端网关**回的 500 | 1.0s 内失败、`token=0`、URL 是 `opencode.ai/zen/go/v1`；同一时刻游戏桥 RPC 全部正常 |
| ② | 「网关挂了，过会儿再试」 | **这个模型不挂在这条协议路上**，等多久都不会好 | 同 key / 同 base_url / 同自定义头，换个模型立刻 200 |
| ③ | 「OpenAI 兼容就一条路」 | 同一网关**三条协议并存**，模型各归各路 | OpenCode 自己的端点表（29 行）：16 个在 `/chat/completions`、9 个在 `/messages`、4 个在 `/responses` |

三条协议（`union-alpha` 属第二条，`grok-4.6` 属第三条）：

| 模型 | `/chat/completions` | `/messages` | `/responses` |
|---|---|---|---|
| `union-alpha` | **500** 裸 `Internal server error` | **200**（`x-api-key`） | 500 |
| `grok-4.6` | 401 `not supported for format oa-compat` | 401 `not supported for format anthropic` | **200** |
| `mimo-v2.5` | **200** | — | — |

★ 关键认识：网关**有时会自己报出格式名**（`not supported for format <x>`），有时只回一个裸 500
（`union-alpha` 就是后者）—— 前者可以当判据，后者只能当"疑似"。**两条要分开对待**，
否则要么漏切（用户永远全哑）、要么乱切（每次对话白发请求）。

#### 实测出来的全部 wire 事实（照文档猜会踩的四处）

`/messages`（Anthropic）：**① `system` 是顶层字段**（写进 messages 判非法）；
**② `max_tokens` 必填**（缺了回 400 `max_tokens is required and must be a positive integer`）；
**③ 鉴权走 `x-api-key`**（只发 `Authorization: Bearer` → 401 `Missing API key`；两个都发是 200）；
**④ 工具结果是 user 消息里的 `tool_result` 块**（`tool_use_id` 回指，没有 role:tool），
且 `tool_result` 必须**排在同一条消息的文字之前**。用量的 `input_tokens` **不含**缓存命中。

`/responses`（OpenAI Responses）：`input` 是**扁平条目列表**（role 消息与 `function_call` /
`function_call_output` 并列）；system 走顶层 `instructions`；工具定义**扁平**
（不套 `function` 键）；助手历史用 `output_text` 回放；流式事件前缀 `response.`
（思考是 `response.reasoning_summary_text.delta`，是**摘要**不是原始思维链）；
用量键名同 OpenAI 且 `input_tokens` **含**缓存命中 —— **与 Anthropic 口径相反**。
仓库自带的 9 个工具 schema（9035 字符）实测原样可用，模型还正确调了 `inspect_unit`。

#### 实现：骨架一份，协议三条

`openai_client` 抽出三个**协议钩子**（`_wire_request` / `_event_parser` / `_parse_response`
+ 已存在的 `_open_stream` / `_call`），默认实现 = 原 OpenAI 行为**逐字节不变**；
`anthropic_client` 与 `responses_client` 只覆盖钩子。为什么这么做：看门狗（首字/停顿）、
重试、"已推 token 就不重试"、放弃时 close 流这一整套是 **09-14 / 09-17 两次线上事故**换来的，
抄一份等于以后要修两遍而**一定会**只修一半 —— 故有一条契约测试直接断言"不许重写 generate"。

HTTP/SSE 传输抽到 `llm/_http.py`（三条路只有路径、鉴权头、协议版本头三处差异）。

`llm/auto_client.py`：`auto`（默认）依次试 **openai → anthropic → responses**，命中即锁定。
三条安全边界：
1. **只在"一个 token 都没推出去"时切换**（包装 on_token/on_reasoning 计数得知）——
   中途换协议重发会把同一段话给玩家演两遍；
2. **只认"协议不对"的签名**才切（`oa-compat` / `not supported for format` / 那记裸 500），
   网络超时与 503 一律不切 —— 它们与协议无关，切了只会把等待翻倍；
3. **以定性失败收场（格式错/模型不存在/鉴权错）才置"存疑"，之后不再试探**，直到主协议
   有一次成功调用；若末条是 503/429/超时这类瞬时失败则不置存疑（那条路可能只是上游在抖）。

配置面：新增 `llm.protocol`（`auto`/`openai`/`anthropic`/`responses`，默认 `auto`）与
`llm.max_tokens`（**仅 anthropic 用**，该协议必填；默认 8192）。两键都进了
`config_store` 白名单 —— 面板里**没有**这两行（加行要重打 AB 预制件），手编 `config.json`
有效，面板保存不会把它们抹掉（与 `idle_timeout` 同一先例）。探针（「测试连接」）现在会
把**实际用上的协议**报进日志与回包：`model test: ok=True ... protocol=anthropic`。

**真机验收**（09-18，改完即测）：
* `auto` + `union-alpha` → 自己切到 `anthropic`，回 `ok`，`protocol_name=anthropic` 锁定；
* `auto` + `grok-4.6` → 一路试到第三条，回 `pong`，锁定 `responses`；
* `auto` + `mimo-v2.5` → 留在 openai（从未被拒，`protocol_name` 保持 `auto`）；
* `auto` + 9 个真工具（两条路各测一遍）→ 都正确产出工具调用；
* 探针 + `union-alpha` → `ok=True protocol=anthropic`。

#### 顺带修掉的两处（都是"静默"型）

* **同一条 user 消息里 `tool_result` 没前置**：Canonical 的 `[text, tool-result]` 是合法顺序，
  而 Anthropic 要求工具结果块排最前 —— 照原序发出去整趟 400。变异脚本 ⑥c 就是照这条设计的。
* **401 `ModelError` 被当成 key 问题**：模型名写错/模型不在套餐或地区时，网关回的就是
  `401 {"type":"ModelError","message":"Model X is not supported"}`，而通用 auth 建议会说
  「API Key 不对或已失效」—— 把人支去改 key，而他该改的是 `model` 那一行。

#### ★ 环境级坑：变异脚本在 drvfs 上会读到陈旧字节码（本轮最值钱的发现）★

`config_loader.py` 文件里明明写着 `"protocol": "auto"`，`import` 进来却是 `'chat'` ——
上一轮变异留下的 `.pyc` **没有失效**。原因：仓库在 Windows 盘（drvfs）上，`shutil.copy2`
还原后源文件 mtime 与变异时落在**同一秒粒度**里（还有一类变异长度都不变，如 `sum`→`max`），
CPython 的 "mtime+size" 判据于是认为缓存仍有效，**继续执行上一轮的变异版字节码**。
后果是变异结果**双向失真**：真变异可能报"没捕获"，也可能把上一轮的变异算到这一轮头上。
修法在 `scripts/dev/_mutate_lib.py`（一处）：`sys.dont_write_bytecode = True` **加上**
`sys.pycache_prefix` 指到仓库外 —— 前者不写、后者不读。**只做前者不够**（挡不住读旧 pyc）。

#### 已知限制（都是实测，不是猜）

* `/responses` 带图：opencode 对 `grok-4.6` 回 `400 Error from provider (Console Go):
  Upstream request failed`（无细节）。规范形态照发（真 OpenAI 端点支持），**不在本地偷偷丢图**；
  要用图就选支持视觉的模型/协议，或用 `image.enabled=false` 关掉截图。
* `llm.max_tokens` 只作用于 anthropic；`/responses` **刻意不发** `max_output_tokens` ——
  该协议的推理 token 也计入 output（实测"只回两个字"烧掉 278 个推理 token），
  拿 8192 去卡它会把长思考的回复截断。上界由两个存活看门狗负责。
* `auto` 的识别成本：每个内芯实例最多白跑 2 次 ×(retries+1)。默认 `retries=1` 时
  约 4 次请求 / ~3s，**一次性**（改配置才会重建内芯）。刻意不为省这几秒去改
  `_is_retryable`：那记裸 500 的签名太松，拿它压制重试会把正常的瞬时 500 也变成不重试。
* 地区限制（与本功能无关，用户本地区实测）：`gpt-5.6-luna`、`muse-spark-1.2/1.3-contributor`
  回 403 `Country, region, or territory not supported`；`kimi-k2.5` 回 400
  `Model is unavailable`（且它不在 Go 的模型表里）。
